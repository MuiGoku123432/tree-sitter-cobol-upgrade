# Requirements: v0.26.0 Estate Parse Recovery

**Defined:** 2026-09-17
**Core Value:** Raw estate COBOL becomes a source-mapped, measurable AST whose graph-relevant
identifiers remain accurate and whose degraded parses are routed for review rather than silently
trusted.

## v0.26.0 Requirements

### Foundation

- [ ] **FOUND-01**: The top-level `preprocessor/` Go 1.23 module builds and consumes the existing
  forest shim without changing the shim's module identity, generated-artifact ownership, or public
  API.
- [ ] **FOUND-02**: Input bytes remain immutable, generated outputs never alias caller buffers, and
  all persisted artifacts are written atomically with restrictive permissions to canonical,
  symlink-safe roots outside the corpus and public repository.
- [ ] **FOUND-03**: Identical input bytes, configuration, tool versions, and manifest membership
  produce byte-identical generated source, maps, ledgers, diagnostics, records, clusters, and
  canonical JSON regardless of discovery or worker order.

### Preprocessing

- [ ] **PREP-01**: Fixed-format preprocessing treats columns 1-6, column 7, columns 8-72, and
  columns 73-80 as distinct byte regions; it preserves comments, suffixes, line-ending provenance,
  short lines, tabs, UTF-8 bytes, and true continuation semantics without implicit trimming.
- [ ] **PREP-02**: Exact Endevor `-INC <MEMBER>` directives in the COBOL code area become
  parser-legible `COPY <MEMBER>.` forms with provenance, while comments, literals, near misses,
  unresolved names, and cycles produce explicit diagnostics rather than guessed rewrites.
- [ ] **PREP-03**: Only `IDMS-CONTROL SECTION`, `PROTOCOL`, `SCHEMA SECTION`, and `DB ... WITHIN ...`
  structural forms are neutralized; grammar-native IDMS DML, CICS, SQL, standard COBOL, and their
  graph-bearing operands remain byte-for-byte unchanged.
- [ ] **PREP-04**: Every non-identity transformation emits an ordered, schema-versioned ledger entry
  with stable rule identity, reason, original pieces, generated range or deletion marker, and
  input/output hashes; no source edit is silent.

### Provenance

- [ ] **MAP-01**: Every generated byte and boundary maps to exact original source pieces or an
  explicit synthetic anchor; generated and original coordinates are zero-based byte ranges with
  rows and columns derived from exact bytes.
- [ ] **MAP-02**: Deleted spans, rewritten spans, insertions, continuation joins, and one-to-many
  origins remain representable in both lookup directions without inventing a coordinate or
  collapsing multiple origins into a false exact range.
- [ ] **MAP-03**: Unit, property, and fuzz tests prove complete generated coverage, zero overlap,
  in-range spans, deterministic composition, boundary-bias behavior, and exact round trips for
  copied bytes across line-ending and fixed-format edge cases.

### Parse Quality

- [ ] **QUAL-01**: The parser adapter distinguishes timeout/no-tree/invocation failure from a
  returned recovery tree and records `ERROR` and `MISSING` nodes separately with generated ranges,
  original mapped pieces, nearest named ancestry, affected structural region, retained anchors,
  data items, paragraphs, and graph-bearing captures.
- [ ] **QUAL-02**: A pure, versioned policy assigns exactly one green, amber, or red grade with
  ordered reason codes; timeout, no tree, invalid/incomplete maps, missing required anchors,
  division-scale recovery, retained-structure collapse, or lost/unmapped graph captures are
  non-compensable red conditions.
- [ ] **QUAL-03**: Stored parse facts can be regraded under a new policy without reparsing, and the
  same facts plus policy version always produce byte-identical grade output.

### Review Queue

- [ ] **REV-01**: Every amber or red outcome creates an immutable, idempotent occurrence record
  containing stable input/tool/config identities, facts, grade/reasons, mapped evidence,
  transformation summaries, privacy class, cluster identity, and lifecycle state.
- [ ] **REV-02**: A versioned structural signature groups recurring failures deterministically
  without raw source text, file paths, member names, literals, or business identifiers; cluster
  occurrence totals always reconcile to degraded outcomes and never overwrite observations.
- [ ] **REV-03**: Offline provider-neutral review packets are built from an allowlisted schema,
  remain size-bounded, pass prohibited-field and canary-leak scans, and contain no raw/transformed
  estate source, reconstructable source map, credentials, provider SDK, network call, or model
  invocation.
- [ ] **REV-04**: Review lifecycle records classification, disposition, and resolved/persistent/
  split/merged/new lineage without deleting prior observations.

### Benchmark

- [ ] **BENCH-01**: A frozen manifest reconciles exactly 3,781 declared COBOL members and 1,369
  compilable programs with a stable membership digest, deterministic development/holdout split,
  and exactly one recorded outcome for every program; incomplete denominators fail closed.
- [ ] **BENCH-02**: Two fresh same-version runs and single-worker versus approved multi-worker runs
  produce byte-identical canonical transformed source, maps, assessments, records, clusters,
  manifests, and summaries; timing remains noncanonical metadata.
- [ ] **BENCH-03**: Paired baseline/candidate comparison reports every grade, ERROR/MISSING,
  recovery-span, retained-structure, graph-capture, mapping, timeout/failure, and cluster transition;
  denominator drift, new hard-red outcomes, green regressions, mapping regressions, and graph-
  capture loss fail the comparison.

### Recovery Loop

- [ ] **REC-01**: Every material residual cluster is classified as preprocessor, source-map,
  include/catalog, grammar, malformed input, accepted degradation, or infrastructure before a fix
  is proposed.
- [ ] **REC-02**: A recovery candidate is promoted only with affected-program count, severity and
  retained-structure impact, normalized signature, correct preprocessing/map evidence, an invented
  minimal reproducer, expected benchmark movement, and explicit regression gates.
- [ ] **REC-03**: Selected high-impact fixes reduce or resolve their target signatures on the
  development set and remain stable or better on the sealed holdout, with no new hard-red outcome,
  green regression, mapping regression, graph-capture loss, NIST regression, or existing parser-
  contract failure.

## Future Requirements

### Integration

- **INT-01**: Gortex production indexing consumes the source-mapped preprocessing and quality API.
- **INT-02**: An approved internal model classifies minimized review packets and records auditable
  suggestions without receiving raw estate source.
- **INT-03**: Operators can inspect and manage review clusters through a UI or ticketing workflow.

### Language Breadth

- **LANG-01**: Explicit catalog-driven recursive `COPY` expansion supports cycle detection and
  multi-origin source maps.
- **LANG-02**: The site macro/percent-macro language is handled by a dedicated, measured stage.
- **LANG-03**: Additional low-volume COBOL grammar families are implemented when benchmark clusters
  justify them.

## Out of Scope

| Feature | Reason |
|---------|--------|
| External AI/model invocation | This milestone creates safe offline packets only; provider approval, cost, and data governance are separate decisions. |
| Automatic AI-authored patches | Review suggestions require deterministic reproduction, tests, and human approval. |
| UI, dashboard, ticketing, or multi-user review service | The milestone delivers records, clusters, packets, and CLI/library contracts. |
| Production Gortex extractor adoption | This milestone proves the parser-neutral integration seam; production cutover is a later milestone. |
| Arbitrary recursive COPY expansion | v0.26.0 handles exact `-INC` rewriting and explicit diagnostics, not an ambient include engine. |
| General site-macro processing | It is a separate language and requires its own measured scope. |
| Full SQL grammar or `EXEC DLI` | Not required for the measured recovery objective; DLI has zero estate occurrences. |
| Alternate COBOL parser | The existing enhanced Tree-sitter grammar and forest shim remain authoritative. |
| Raw estate source in Git, reports, packets, logs, or fixtures | The repository is public and estate data is proprietary. |
| Performance SLO | Timing is measured in the first benchmark; no target is invented before evidence exists. |
