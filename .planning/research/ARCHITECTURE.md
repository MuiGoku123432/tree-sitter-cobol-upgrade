# Architecture Patterns

**Domain:** Source-mapped COBOL preprocessing, parse-quality assessment, and secure review evidence
**Milestone:** v0.26.0 Estate Parse Recovery
**Researched:** 2026-09-17
**Overall confidence:** HIGH for repository boundaries and measured behavior; MEDIUM for proposed public APIs and thresholds

## Recommendation in One Sentence

Build `preprocessor/` as an independent, pure Go module that owns immutable-input transformation, byte-accurate provenance, parse assessment, deterministic artifact storage, and offline packet export; keep `forest-shim/cobol/` byte-faithful to the third-party parser package, and connect the two only in a benchmark/integration command that injects a parser adapter.

## Evidence That Drives the Design

- `forest-shim/cobol` deliberately impersonates `github.com/alexaandru/go-sitter-forest/cobol`; its compatibility surface is only `GetLanguage`, `GetQuery`, and `Info`, and `refresh.sh` verifies `binding.go`, `plugin.go`, and `go.mod` against forest v1.9.1. Adding preprocessing or assessment APIs there would break the drop-in boundary.
- Gortex currently uses the shim only through its parser pointer in `cobolprobe`. Production COBOL indexing still uses the regex extractor. The milestone should therefore ship an explicit integration seam, not quietly alter Gortex's generic forest or regex contracts.
- Tree-sitter reports a best-effort tree. Its official documentation distinguishes `(ERROR)` from zero-width `(MISSING)` recovery nodes, and nodes expose byte ranges plus row/column points. Both node classes must feed quality assessment.
- Tree-sitter columns are byte columns, not rune columns. Mapping must therefore be byte-first. Original line/column values should be derived from original bytes after range projection, never projected independently from transformed points.
- Existing estate measurements prove that error count alone is misleading: few ERROR nodes can span most of a division. Assessment must include merged error coverage, maximum error span, and retained data-item/paragraph structure.
- `run_accept_differential.sh` already establishes useful safety conventions: sorted relative paths, complete-denominator checks, explicit timeouts, external scratch space, no source text in inventories, and refusal to write corpus-derived output under the public repository.

## Recommended Architecture

```text
read-only consolidated estate
          |
          v
 preprocessor.Transform(original bytes, policy)
          |
          +--> Document.OriginalSHA256
          +--> Document.Generated []byte
          +--> SourceMap (generated byte boundary -> original provenance)
          +--> Transform events/diagnostics
          |
          v
 injected Parser.Parse(Document.Generated)
          |
          v
 assessment.Assess(AST observations, SourceMap, source-truth counters)
          |
          +--> original-coordinate findings
          +--> Grade: green | amber | red
          +--> deterministic failure signature
          |
          v
 bucket.Store(record) --> <artifact-root>/<bucket>/<record-id>/record.json
          |
          +--> benchmark aggregation/differential
          +--> packet.Export(red/amber record, explicit policy)
          |
          v
 minimized provider-neutral packet outside public worktree
          |
          v
 reviewed recurring signatures --> hand-written fixture --> grammar change
                                  --> refresh shim --> gates --> rebenchmark
```

The system should be a library-first pipeline with a thin command under `preprocessor/cmd/estate-bench`. Do not make shell text scraping the primary architecture. Shell may orchestrate the command, but typed Go records should be the contract between transformation, parsing, assessment, storage, and export.

## Module and Dependency Boundaries

### Top-level module

Use a separate module at `preprocessor/go.mod`. Its module path should be a new project-owned path, not a subpackage of the impersonated forest module. The exact published module path can be chosen during implementation, but the dependency direction is fixed:

```text
preprocessor core packages       no dependency on forest-shim/cobol
benchmark/integration command    imports preprocessor + forest-shim/cobol
forest-shim/cobol                imports neither preprocessor nor benchmark code
gortex                           optional future consumer; unchanged for the milestone core
```

Because Go cannot import an `internal/` package from another module, public contracts used by a future Gortex adapter must live in importable packages. Recommended layout:

```text
preprocessor/
  go.mod
  document.go              public Transform API and immutable Document
  sourcemap.go             public generated-to-original mapping API
  assessment.go            public observations, report, grade, policy
  transform/
    fixed.go               columns 1-6, indicator, code area, identification area
    continuation.go        deterministic fixed-format continuation handling
    endevor.go             -INC rewrite
    idms.go                structural-line neutralization
    pipeline.go            ordered transform composition
  bucket/
    store.go               deterministic content-addressed records
  packet/
    export.go              minimized, policy-checked packet export
  internal/cobolfmt/       line scanner and fixed-format primitives
  cmd/estate-bench/        corpus selection, parser wiring, aggregation, compare
```

Package names can be adjusted, but these responsibilities should not collapse into one package. In particular, `packet` must consume an assessment record, not raw source or a Tree-sitter node, and `bucket` must not know how parsing works.

### Forest shim remains a leaf adapter

`forest-shim/cobol/` must remain limited to the exact forest-compatible generated parser package:

- `go.mod` keeps module identity `github.com/alexaandru/go-sitter-forest/cobol`.
- `binding.go` / `plugin.go` retain the three exported functions and embed behavior.
- Generated C, header, grammar JSON, and query files remain refreshed atomically by `forest-shim/refresh.sh`.
- No source-map, preprocessing, assessment, packet, benchmark, or storage code enters this directory.
- The preprocessor must not be added as a dependency of the shim. The shim is generated-parser delivery, not an application layer.

This preserves `go.work` substitution for Gortex and keeps the existing drift check meaningful.

### Parser adapter

The assessment layer should not import Gortex internals. Define a narrow parser-neutral observation contract in the preprocessor module:

```go
type GeneratedRange struct {
    StartByte uint64
    EndByte   uint64 // half-open
}

type ParseObservation struct {
    Kind       string
    Range      GeneratedRange
    Missing    bool
}

type ParseSnapshot struct {
    RootRange          GeneratedRange
    Failures           []ParseObservation // ERROR and MISSING
    DataItems          uint64
    ParagraphHeaders   uint64
    IDMSNodes          uint64
    CICSNodes          uint64
    SQLNodes           uint64
}

type Parser interface {
    Parse(ctx context.Context, generated []byte) (ParseSnapshot, error)
    Fingerprint() ParserFingerprint
}
```

The integration command implements this interface with `forest-shim/cobol.GetLanguage()` and `go-tree-sitter`. This keeps the preprocessor testable with a fake parser and prevents CGO/generated artifacts from contaminating the core module. It also leaves a clean future boundary for Gortex: Gortex can consume `Document.Generated`, retain the map beside its parse tree, and project every emitted node/edge range before graph persistence.

## Original-Source Immutability

Original-source immutability is an architectural invariant, not a coding convention.

### Contract

```go
type Document struct {
    Generated      []byte
    Map            SourceMap
    OriginalSHA256 [32]byte
    PolicyID       string
    Events         []TransformEvent
}

func Transform(original []byte, policy Policy) (Document, error)
```

Required behavior:

1. Treat `original` as borrowed read-only memory. Never reslice it for output and never mutate it in place.
2. Allocate a distinct generated buffer, including on an identity transformation. This prevents a caller from observing aliasing and accidentally invalidating hashes or provenance.
3. Hash the exact original bytes before transformation. Hash generated bytes after transformation. Record both in assessment and bucket metadata.
4. The library accepts bytes, not paths, and performs no writes. Only commands/adapters open files.
5. Benchmark mode opens source read-only and writes only under an explicitly supplied artifact root that must resolve outside the source corpus and outside this public repository.
6. Tests must assert: original bytes are unchanged, generated storage does not alias original storage, repeated runs are byte-identical, and every generated boundary is mappable.

Do not use the existing Gortex `PreParser` interface as the milestone contract. That interface requires identical byte length and newline placement. It is suitable for masking transforms, but not for `-INC` expansion, continuation reflow, synthetic copybook shells, or any transformation requiring a real source map. A future Gortex integration should add a source-mapped capability rather than weakening `PreParser`'s invariant.

## Source-Map Representation

### Canonical representation: monotone segments over byte boundaries

Represent provenance as a sorted, gap-free sequence of half-open generated byte intervals:

```go
type OriginKind string

const (
    OriginCopy      OriginKind = "copy"
    OriginRewrite   OriginKind = "rewrite"
    OriginSynthetic OriginKind = "synthetic"
)

type Segment struct {
    GeneratedStart uint64
    GeneratedEnd   uint64
    OriginalStart  uint64
    OriginalEnd    uint64
    Kind           OriginKind
    Rule           string // stable rule ID, e.g. endevor-inc/v1
}

type SourceMap struct {
    Version       uint32
    OriginalBytes uint64
    GeneratedBytes uint64
    Segments      []Segment
}
```

Invariants:

- Segments are sorted by `GeneratedStart`, non-overlapping, and cover `[0, GeneratedBytes)` exactly.
- Original intervals are monotone non-decreasing. Copy segments are one-to-one and satisfy equal lengths.
- Rewrite segments retain the complete original interval responsible for generated text, even when lengths differ.
- Synthetic segments are zero-width anchors in original space: `OriginalStart == OriginalEnd`. The anchor is the boundary immediately before the insertion, or EOF for a trailing synthetic shell.
- Adjacent segments may be coalesced only when kind, rule, and mapping slope are identical.
- The map version and transform policy ID are persisted. Mapping semantics must never change silently.

### Why byte offsets are authoritative

Tree-sitter exposes `StartByte`/`EndByte` and zero-based points whose columns count bytes. The mapper should project generated half-open byte ranges first. It should then calculate original line/column from a precomputed original newline index. This avoids three common bugs:

- treating UTF-8 byte columns as rune columns;
- independently mapping start/end rows after continuation folding;
- losing precision when a rewrite changes line length but not line count.

### Point and range projection API

```go
type Bias uint8
const (
    BiasLeft Bias = iota
    BiasRight
)

type OriginalPoint struct {
    Byte   uint64
    Row    uint32 // zero-based
    Column uint32 // byte column
    Exact  bool
    Synthetic bool
}

type OriginalRange struct {
    Start OriginalPoint
    End   OriginalPoint
    Pieces []OriginalSpan
    Exact bool
}

func (m SourceMap) OriginalPoint(generatedBoundary uint64, bias Bias) (OriginalPoint, error)
func (m SourceMap) OriginalRange(r GeneratedRange) (OriginalRange, error)
```

Range mapping rules:

1. Treat Tree-sitter ranges as half-open `[start, end)` boundaries.
2. Map the start with right bias and the end with left bias. This prevents a boundary between segments from jumping outside the contributing original span.
3. Return all contributing `Pieces`, not only a bounding box. Continuation folding can make a generated token span multiple non-contiguous original line fragments.
4. `Exact=true` only when every byte in the generated range comes from one-to-one copy segments. A range touching rewritten or synthetic bytes is approximate even if its bounding coordinates look plausible.
5. A zero-width MISSING node maps as a point with both biases available. Record the chosen diagnostic convention, preferably right bias for insertion-at-boundary diagnostics.
6. For graph nodes whose captured identifier lies wholly in a copied segment, emit exact original coordinates. If a capture crosses rewritten/synthetic text, do not fabricate an exact source location. Emit the covering original range plus `mapping_exact=false` and retain pieces for audit.

### Transform mechanics

Use a source-map builder that appends output and provenance together. A transform must never edit generated bytes without appending the corresponding segment in the same operation:

```go
builder.Copy(original[start:end], start, end, ruleID)
builder.Rewrite(replacement, start, end, ruleID)
builder.Insert(replacement, anchor, ruleID)
```

Run transforms in a fixed versioned order, recommended:

1. Normalize newline interpretation without silently changing bytes; detect CRLF/LF and preserve an original newline index.
2. Classify fixed/free format and enforce columns 1-6, indicator column 7, code area 8-72, and identification area 73-80 policy.
3. Join/normalize continuation semantics.
4. Rewrite Endevor `-INC MEMBER` into parser-legible `COPY MEMBER.`.
5. Neutralize only the structural IDMS lines assigned to preprocessing.
6. Add a synthetic program shell only for explicitly classified fragments/copybooks, never for compilable programs.

If one transform consumes the previous transform's output, compose its map back to the original immediately. The public `Document.Map` must never require consumers to replay a chain of intermediate maps.

## Parse Assessment API

### Separate observation from policy

Collection must be grammar/runtime-specific; grading must be pure and versioned:

```go
type AssessmentInput struct {
    SourceID       string
    OriginalHash   [32]byte
    GeneratedHash  [32]byte
    TransformID    string
    Parser         ParserFingerprint
    Snapshot       ParseSnapshot
    Truth          RetainedStructureTruth
    Map            SourceMap
}

type Assessment struct {
    SchemaVersion  uint32
    Grade          Grade // green, amber, red
    ReasonCodes    []string
    Metrics        Metrics
    Failures       []Failure
    Signature      string
}

func Assess(in AssessmentInput, policy AssessmentPolicy) (Assessment, error)
```

`Failure` should contain node kind, generated range, projected original range/pieces, mapping exactness, and a normalized context signature. It must not contain raw source by default.

### Metrics

At minimum collect:

- ERROR count and MISSING count separately;
- union of lines covered by ERROR ranges;
- maximum ERROR span in lines and bytes;
- root coverage and parse timeout/failure state;
- parsed `data_description*` count and `paragraph_header` count;
- source-truth data-item and paragraph counts using the existing fixed-format counting method;
- recovery ratios for both structures;
- counts of IDMS/CICS/SQL named nodes;
- transform event counts by stable rule ID;
- number and proportion of approximate/synthetic failure mappings.

The current estate assessment shows why these dimensions matter: 3,223 ERROR and 347 MISSING nodes across 1,369 programs, but ERROR ranges cover 53.31% of all source lines; 893 files have a maximum span of at least 100 lines. One error can therefore be red even when the count is one.

### Grading policy

Do not hard-code an unvalidated formula into the data model. Version a policy and start with conservative gates:

- **Green:** parse completed; zero ERROR and MISSING nodes; required structure present when source truth expects it; all graph-bearing captures map exactly to original bytes.
- **Red:** parse failed/timed out; source-map validation failed; an ERROR span crosses a division boundary or exceeds the policy's large-span limit; expected data items or paragraphs collapse to zero; recovery falls below a measured threshold; or a graph-bearing capture has no original provenance.
- **Amber:** all other non-clean parses, including localized ERROR/MISSING nodes with retained structure and valid provenance.

Threshold numbers should be calibrated from a checked-in synthetic suite plus the full 1,369-program benchmark. The grade must include ordered reason codes so a result is explainable and differential-friendly. Never grade solely on `root.HasError()` or total error count.

### Consumer rule

- Green records may be indexed normally.
- Amber records may be indexed only with an explicit degraded-provenance marker and must enter the review bucket.
- Red records are quarantined from authoritative graph emission by default, but their metrics and minimized review record are retained.

This is the point where Gortex eventually integrates. The mapping must happen before graph nodes/edges are persisted, because current Gortex extractors directly use transformed `StartPoint` rows. A source-mapped COBOL extractor must wrap every captured range through `SourceMap.OriginalRange` and continue to use the original file path as identity.

## Deterministic Bucket Storage

### Content-addressed record identity

Use a record ID derived only from stable inputs:

```text
record-id = sha256(
  schema-version || original-sha256 || generated-sha256 ||
  transform-policy-id || parser-fingerprint || assessment-policy-id
)
```

Do not derive identity from source path, wall-clock time, host name, iteration order, absolute corpus root, or grade. A grade can change when policy changes; that is why policy ID belongs in the key material.

### Layout

```text
<artifact-root>/
  green/<record-id>/record.json
  amber/<record-id>/record.json
  red/<record-id>/record.json
  manifests/<run-id>.json
  packets/<packet-id>.json
```

`record.json` contains hashes, metrics, projected ranges, reason codes, transform events, and parser/policy fingerprints. It contains no raw source and no absolute path. Store a stable opaque `source_id`, preferably an HMAC-SHA256 of normalized relative path with a local secret when even member names are sensitive. Plain relative paths are acceptable only in a private local bucket, never in an export packet.

### Determinism and atomicity

- Enumerate normalized relative paths in bytewise lexical order before parallel work.
- Let workers compute immutable records, then sort by record ID before manifest serialization.
- Use typed structs and arrays rather than semantically unordered maps in canonical artifacts.
- Marshal with one pinned encoder policy; append exactly one final newline.
- Write to a same-directory temporary file with mode `0600`, sync/close, then rename atomically.
- If an existing record ID has different bytes, fail closed as a hash/canonicalization invariant violation. If identical, treat the write as idempotent.
- Do not put timestamps in content-addressed records. Run manifests may carry time as non-identity metadata, but byte-for-byte reproducibility tests should omit or normalize it.
- Reject artifact roots under the repository, under the corpus, or resolving through symlinks into either. Reuse the canonical-path fail-closed posture from `run_accept_differential.sh`.

A database is unnecessary at 1,369 programs. A filesystem CAS plus deterministic JSON is inspectable, diffable, easy to rebuild, and avoids schema/migration work before the quality model settles.

## Secure Provider-Neutral Packet Export

Treat packet generation as an explicit declassification boundary. The default operation exports nothing.

### Packet shape

```go
type ReviewPacket struct {
    SchemaVersion uint32
    PacketID      string
    RecordID      string
    Grade         Grade
    ReasonCodes   []string
    Metrics       Metrics
    Failures      []PacketFailure
    TransformSummary []RuleCount
    Parser        ParserFingerprint
    Reproduction  ReproductionDescriptor
}
```

A packet may contain:

- opaque source ID and cryptographic hashes;
- grammar/parser/transform/assessment versions;
- normalized node-kind sequences and failure signatures;
- original-coordinate ranges with identifiers removed;
- aggregate structure counts and transform counts;
- small context windows only after a deterministic redactor proves they satisfy an allowlist.

It must not contain by default:

- raw original or generated files;
- absolute paths, member names, system/subsystem names, usernames, hostnames, or repository roots;
- arbitrary AST text, string literals, comments, COPY member names, SQL table names, CICS operands, IDMS record/set names, or sequence-area content;
- source maps detailed enough to reconstruct transformed source;
- credentials or environment dumps.

### Redaction and validation

Use token-class replacement, not ad hoc regex deletion after serialization. Build packet context from an allowlisted intermediate representation such as:

```text
IDENTIFIER KEYWORD IDENTIFIER PERIOD
ERROR_RANGE(lines=3, node_path=...)
```

Then run a fail-closed export validator:

- byte/line/item caps;
- no absolute/local path prefixes;
- no unexpected JSON fields;
- no control characters outside JSON escaping;
- no original substring above a small configured length;
- optional high-entropy/secret scan;
- recompute packet ID from canonical packet bytes.

Export individual canonical JSON files or a deterministic tar only when bundling is required. If tar is used, sort entries and set mode, uid/gid, user/group names, and timestamps to fixed values. Do not include symlinks. The module performs no network call and has no provider SDK dependency. A human explicitly moves the packet to a model/provider later.

## Benchmark Flow

Retain the existing 1,369-program denominator and differential discipline, but move the core measurement into the typed command:

```text
estate-bench run
  --corpus <read-only-root>
  --artifacts <external-private-root>
  --parser current
  --policy <version>
  --workers N

estate-bench compare
  --before <manifest>
  --after <manifest>
```

### Run sequence

1. Canonicalize corpus and artifact roots; refuse overlap or containment in the public repo.
2. Select programs with the existing authoritative condition: both `IDENTIFICATION DIVISION` and `PROCEDURE DIVISION`; assert the recorded 3,781 members / 1,369 programs unless an explicit new-corpus mode is used.
3. Sort relative paths. Hash original bytes before any transform.
4. Transform to a fresh generated buffer and validate source-map invariants.
5. Parse with a timeout through the injected current shim adapter.
6. Collect ERROR and MISSING ranges and retained-structure counters in one tree walk.
7. Project every diagnostic range to original coordinates.
8. Assess, store one canonical record, and update aggregate counters.
9. Emit a sorted run manifest and summary only after every selected file has a result. Any read/parse/write failure makes the denominator incomplete and the command fails.
10. Re-run the same command and require identical record/manifest content hashes, excluding explicitly noncanonical run metadata.

### Differential

Compare records by opaque source ID and report:

- grade transitions, especially green to amber/red;
- ERROR/MISSING count deltas;
- error-covered-line and maximum-span deltas;
- data-item and paragraph recovery deltas;
- graph-bearing node count deltas;
- transform-rule count changes;
- new/resolved normalized failure signatures;
- mapping exactness regressions.

Keep `run_accept_differential.sh` as the grammar collision gate for existing node-type guarantees. Do not overload it into the new end-to-end benchmark: it is intentionally specialized around before/after node inventories and its security assumptions are useful precedents, not a reusable application API.

## Grammar Feedback Loop

The feedback loop must turn repeated post-preprocessing evidence into generic grammar work without leaking estate content:

1. Cluster amber/red failures by deterministic signature: node kind, normalized parent/child path, nearby keyword classes, mapped span shape, transform rule IDs, and parser fingerprint.
2. Rank by affected program count and structural loss, not raw ERROR count. A one-node division cascade outranks many isolated one-line errors.
3. Inspect raw source only locally and manually for the highest-impact clusters.
4. Decide ownership:
   - non-COBOL/site structural syntax or fixed-format mechanics -> preprocessor rule;
   - valid, generic COBOL/IDMS/CICS/SQL syntax whose operands must remain graph-visible -> grammar;
   - malformed/ambiguous proprietary material -> review policy, not automatic widening.
5. Reduce the pattern to a minimal, invented, non-estate fixture.
6. For grammar work, add corpus/query tests, regenerate `src/`, refresh the shim, run cascade/query/NIST gates, and run collision differentials.
7. Re-run the 1,369-program benchmark against the same manifest; require no green regressions, no mapping regressions, and a measurable reduction in the target signature/structural loss.
8. Keep grammar commits separate from fork-local preprocessor and evidence changes under FORK-03.

Never promote a raw packet or estate excerpt into `test/corpus`. A cluster signature is evidence for what to hand-author, not fixture material.

## Integration With Gortex

### Current state

- `cobolprobe` imports `github.com/alexaandru/go-sitter-forest/cobol` and directly parses source with Gortex's Tree-sitter wrapper.
- Gortex's production `CobolExtractor` remains regex-based and assigns source lines directly from its input.
- Gortex's generic `PreParser` can only support exact-length/newline-preserving rewrites.
- Gortex already knows how to count ERROR/MISSING nodes on retained parse trees, but its current location API returns transformed positions and caps locations; it does not carry a source map.

### Recommended future seam

Introduce a COBOL-specific orchestrator in Gortex only after this module's contracts stabilize:

```text
original bytes
  -> preprocessor.Transform
  -> Tree-sitter COBOL extractor over Generated
  -> map captures/errors to original coordinates
  -> assess
  -> emit or quarantine according to grade
```

Do not make the generic forest extractor depend on this project. Instead, register a bespoke COBOL extractor that composes the two modules. That extractor can preserve Gortex's `Extractor` interface while internally owning a `Document`, parser tree, and assessment. Any retained parse-tree handle must keep generated source plus source map together for its full lifetime; returning a tree with only original bytes would make `Node.Content` invalid, while returning only generated bytes would make graph coordinates dishonest.

A practical Gortex-side handle should therefore conceptually contain:

```go
type SourceMappedParse struct {
    Tree      *ParseTree       // Tree.Source() is generated bytes
    Map       SourceMap
    SourceID  string           // original identity
    Assessment Assessment
}
```

Graph emitters consume generated bytes for capture text but must project ranges through `Map` before writing line/column metadata. This is a hard boundary: never let transformed coordinates cross into the graph store as if they described the original file.

## Patterns to Follow

### 1. Functional core, imperative shell

**What:** Pure transformation/mapping/assessment functions, with filesystem traversal and artifact writes confined to commands/adapters.

**Why:** It makes immutability and deterministic replay testable without the estate and keeps security checks concentrated at I/O boundaries.

### 2. Append output and provenance atomically

**What:** Every output write goes through the source-map builder.

**Why:** A separate post-hoc mapping pass will drift as soon as continuation and rewrite rules overlap.

### 3. Version every semantic contract

Version transform policies, source-map schema, assessment policy, record schema, packet schema, and parser fingerprint independently. Include those versions in hashes and manifests.

### 4. Complete-denominator failure

A benchmark with one timeout or unreadable program is not a smaller successful benchmark. Fail the run while retaining per-file failure records, matching the existing differential harness's stance.

### 5. Original-coordinate assertions

Fixtures should assert both generated text and mapped original ranges. Include multibyte UTF-8, CRLF, line-end boundaries, inserted text, deleted structural lines, continuation folding, and a Tree-sitter zero-width MISSING node.

## Anti-Patterns to Avoid

### Polluting the forest shim

**Bad:** Add `Transform`, assessment types, or storage dependencies to `forest-shim/cobol`.

**Consequence:** The shim stops being a byte-faithful forest replacement; drift checks fail or become meaningless, and Gortex's import boundary acquires project-specific behavior.

### In-place or file-replacing preprocessing

**Bad:** Rewrite the corpus file and parse it from disk.

**Consequence:** Violates the source-of-truth constraint, makes hashes unverifiable, and risks corrupting proprietary input. Always transform in memory to a new buffer.

### Line-only source maps

**Bad:** Preserve line count and declare coordinates solved.

**Consequence:** `-INC`, fixed-format clipping, continuation folding, and synthetic shells move columns and byte offsets. Tree-sitter and Gortex slice by bytes; line-only maps cannot recover exact operands.

### One generated position to one guessed original point

**Bad:** Collapse rewritten or multi-piece ranges to a single point without an exactness flag.

**Consequence:** Graph edges appear authoritative but point at unrelated source. Return pieces plus explicit exact/approximate provenance.

### Error-count grading

**Bad:** Green/amber/red based only on number of ERROR nodes.

**Consequence:** Existing measurements show one ERROR can consume thousands of lines. Include span and retained structure.

### Exporting transformed source because it is “not original”

**Bad:** Treat generated text as safe to send externally.

**Consequence:** It contains nearly all proprietary identifiers and logic. Generated source is just as sensitive as original source.

### Concurrent direct writes

**Bad:** Have workers append JSON/TSV or create grade directories opportunistically.

**Consequence:** Nondeterministic ordering, partial artifacts, and difficult retries. Workers return records; one ordered writer commits them atomically.

### Parsing transformed bytes but attaching original bytes to the tree

**Bad:** Let `Node.Content` slice original data using generated offsets.

**Consequence:** Wrong text or bounds errors. The tree must remain paired with generated bytes, while coordinates are separately projected to original space.

## Phase Ordering Recommendation

1. **Module skeleton and immutable transform contract**
   - Establish `preprocessor/go.mod`, package boundaries, policy/version fingerprints, and non-aliasing tests.
   - Keep the shim unchanged and prove it still passes its drift/smoke tests.

2. **Source-map core before transformation breadth**
   - Implement segment builder, composition, map validation, byte-first range projection, newline indexes, and exactness semantics.
   - Build property/fuzz tests before adding `-INC` or continuation rules. Every later feature depends on trustworthy mapping.

3. **Fixed-format and transformation pipeline**
   - Implement format classification, columns, continuations, `-INC`, structural IDMS, and optional fragment shell in fixed order.
   - Assert original immutability and deterministic output for each rule and composed cases.

4. **Parser adapter and assessment**
   - Add the shim-backed integration adapter, one-pass AST observations, original-coordinate diagnostics, and versioned grade policy.
   - Calibrate thresholds against synthetic controls and measured estate distributions.

5. **Deterministic bucket and secure packet exporter**
   - Store canonical records outside the repo/corpus; add path containment, atomicity, dedup, and redaction gates.
   - Packet export stays offline and explicit.

6. **Full benchmark and grammar feedback loop**
   - Run all 1,369 programs twice for reproducibility, produce before/after manifests, rank signatures, and feed only generic, hand-written cases into grammar work.

This ordering is dependency-driven: transformations are unsafe without provenance; grading is meaningless without mapped failures and retained-structure metrics; storage and packets need a stable assessment schema; grammar feedback requires reproducible full-estate evidence.

## Scalability Considerations

| Concern | 1,369-program milestone | Larger estate | Recommendation |
|---|---|---|---|
| Parse concurrency | Bounded worker pool | CPU/CGO pressure dominates | Configurable workers; deterministic ordered writer |
| Source maps | Per-document sorted segments | Memory scales with edits, not bytes | Coalesce copy runs; persist only for degraded records unless graph ingestion needs all maps |
| Artifact lookup | Filesystem CAS | Directory fan-out can grow | Use two-character hash prefixes only when record count warrants it |
| Aggregation | In-memory typed summaries | Many runs/history | Stream records, sort IDs externally or migrate manifests to SQLite later |
| Packet review | Manual selected export | Queue growth | Deduplicate by signature and record ID before adding workflow tooling |

## Verification Gates

- `go test ./...` in `preprocessor/`, including fuzz/property tests for map monotonicity, coverage, composition, and boundary bias.
- A fixture matrix for fixed/free format, CRLF/LF, multibyte UTF-8, comments, debug lines, continuation forms, `-INC`, all structural IDMS forms, identity transforms, and synthetic shell anchors.
- Two identical benchmark runs produce identical canonical manifests and record hashes.
- Every Tree-sitter ERROR and MISSING finding maps to a valid original boundary; every graph-bearing capture is exact or explicitly marked approximate.
- Corpus denominator remains 3,781 COBOL members / 1,369 compilable programs, or the run fails with an explicit corpus-version mismatch.
- Artifact and packet roots resolving under the public repository or source corpus are rejected, including symlink traversal.
- Packet tests seed secrets, paths, member names, literals, and long source substrings and prove export fails closed.
- Existing `tree-sitter test`, NIST 371/0/11, query capture gates, cascade gates, shim refresh/smoke tests, and collision differential remain required after grammar changes.

## Research Flags

- **Threshold calibration:** Needs a phase-specific decision after preprocessing measurements. The architecture defines signals and policy versioning, not unjustified green/amber/red numbers.
- **Continuation semantics:** Needs fixture-led research across observed fixed-format variants. Incorrect literal continuation handling can silently change semantics even with a mechanically valid map.
- **Gortex production adoption:** Needs a separate integration design because its current production COBOL extractor is regex-based and its `PreParser` contract assumes identical offsets.
- **Packet redaction:** Needs adversarial tests before any packet leaves the machine. No external model call belongs in this milestone.
- **Path pseudonymization key management:** Decide whether local paths are acceptable in private buckets and whether exported IDs require keyed HMAC rather than raw path hashes.
