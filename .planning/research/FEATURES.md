# Feature Landscape: v0.26.0 Estate Parse Recovery

**Domain:** Deterministic COBOL preprocessing, parse-quality triage, and evidence-driven grammar recovery
**Project:** tree-sitter-cobol-upgrade
**Researched:** 2026-09-17
**Overall confidence:** HIGH for project behavior and measured baselines; MEDIUM for proposed grading thresholds pending benchmark calibration

## Product Contract

This milestone is not another grammar-family expansion. It is the reliability layer between raw consolidated COBOL and graph indexing. It must make transformations reproducible and explainable, preserve a reversible path back to original coordinates, distinguish trustworthy partial trees from dangerous recovery cascades, and turn recurring residual failures into a ranked grammar backlog without exposing proprietary source.

The measured population of record is **1,369 compilable programs** out of 3,781 COBOL members. This is the authoritative denominator for estate benchmark reporting. The current parser can return a tree even when recovery has destroyed most useful structure, so neither process success nor raw ERROR count is an acceptable quality signal. Existing evidence includes a 5,352-line program with only four ERROR nodes but just 5 of 77 paragraphs retained; local cascade tests also show single unsupported constructs reducing downstream retention to 0/20 data items or 1/20 paragraphs. Quality therefore has to combine diagnostics with retained-structure evidence.

No proprietary source was read for this research. All estate claims below come from aggregate project records and diagnostics already committed to the repository.

## Table Stakes

Missing any of these makes the recovery pipeline unsafe, non-reproducible, or operationally incomplete.

| Feature | Required behavior | Acceptance signal | Complexity | Why table stakes |
|---------|-------------------|-------------------|------------|------------------|
| Deterministic preprocessing | Given identical input bytes, configuration, preprocessor version, and include catalog, emit byte-identical parser input, source map, transformation ledger, diagnostics, and hashes. Apply ordered passes for fixed-format interpretation, continuations, Endevor `-INC`, and IDMS structural lines. Never depend on directory iteration order, wall clock, locale, random IDs, or provider behavior. | Repeated runs and shuffled input enumeration produce identical artifact digests; idempotence is either exact or explicitly documented per pass. | High | Benchmark deltas and review deduplication are meaningless if preprocessing drifts. |
| Fixed-format fidelity | Treat sequence area, indicator column, code area, continuation semantics, and identification/sequence suffix as distinct source regions. Preserve comment and continuation intent instead of globally trimming lines. Record the detected/selected source format. | Synthetic boundary matrix covers columns 1-6, 7, 8-72, and 73-80; CRLF/LF and final-newline variants are deterministic. | High | Naive line cleanup silently changes COBOL tokenization and coordinates. |
| Deterministic `-INC` handling | Recognize only the defined Endevor include-directive shape in the correct source region. Resolve through an explicit catalog, detect missing and cyclic references, and record include provenance. Do not crawl the filesystem heuristically or guess near-name matches. | Same catalog yields same expansion order and hash; unresolved/cyclic includes are explicit diagnostics and cannot silently disappear. | High | Includes affect parseability and source ownership; guessing creates non-reproducible trees. |
| IDMS structural-line handling | Neutralize or translate only the explicitly supported structural forms (`IDMS-CONTROL SECTION`, `PROTOCOL.`, `SCHEMA SECTION`, `DB … WITHIN …`) with recognizers anchored to fixed-format code areas. Preserve line/segment provenance and do not erase IDMS DML statement content already modeled by the grammar. | Hand-written positive and near-miss fixtures prove exact matching; DML query captures remain intact after preprocessing. | Medium | Existing evidence assigns the dominant DATA DIVISION blockage to these precompiler-era lines. |
| Reversible source mapping | Map every generated byte interval and point back to original file, byte offset, row, and column. Represent copied, replaced, inserted, deleted, joined, and include-expanded segments explicitly. Define deterministic boundary bias for zero-width and synthetic text. Support generated-to-original lookup as the mandatory direction; retain enough provenance for original-to-generated lookup where one-to-many expansion occurs. | Round-trip/property tests cover unchanged text, deletions, replacements, continuations, CRLF, multibyte bytes, EOF, and nested includes. | Transformation ledger | Emit an ordered, schema-versioned list of transformations with rule ID/version, original and generated ranges, reason code, and before/after hashes. | Green/amber/red grading | Assign exactly one grade using a versioned, deterministic policy over hard failures, ERROR/MISSING placement, diagnostics density, retained structural anchors, and mapping completeness. Store both grade and machine-readable reason codes. Grade per file; aggregate corpus grades separately. | Golden fixtures pin boundary cases. Regrading the same diagnostic record under the same policy version is byte-identical. | High | Downstream indexing needs an explicit trust decision rather than binary parse success. |
| Review-bucket records | Create a durable, schema-versioned record for every amber/red parse, containing stable content/config/parser hashes, grade, reasons, normalized diagnostic signatures, retained-structure metrics, transformation summary, privacy classification, cluster ID, lifecycle state, and evidence references. Update observations without duplicating the issue identity. | Rerunning unchanged input is upsert/idempotent; changed input or parser/config versions remain distinguishable; green transitions close rather than erase history. | Medium | Degraded trees must be routed and auditable, not logged and forgotten. |
| Deterministic clustering | Group degraded records by normalized structural signature, not raw source text or filename. Signature should include mapped diagnostic kind/path, nearest named-node ancestry, division/section context, bounded token classes, transformation reason, and retained-structure loss. Preserve representative examples and cluster frequency. | Input-order permutations produce identical cluster IDs and counts; a cluster split/merge is attributable to an explicit signature-version change. | High | One grammar gap can affect hundreds of files; per-file review wastes effort. |
| Provider-neutral minimized AI packets | Export a local, versioned JSON packet per selected cluster with no provider-specific prompt/messages API. Include aggregate metrics, normalized signatures, relevant node ancestry, transformation facts, source-map excerpts, and a minimal synthetic or structurally redacted reproduction when available. Default-deny raw source and secrets. Invoke no external model. | JSON Schema validation, deterministic serialization, size budget, prohibited-field scan, and privacy test pass. ## Recommended Grade Semantics

The grade names must describe downstream trust, not parser aesthetics. Exact numeric thresholds should be calibrated against the 1,369-program benchmark, but the following hard semantics should be fixed before calibration.

| Grade | Meaning | Required behavior | Hard triggers |
|-------|---------|-------------------|---------------|
| **Green** | Safe for normal graph extraction | Index normally while retaining diagnostics and provenance. | Parser completed; mapping is complete for graph-relevant nodes; required top-level/graph-relevant structure is retained; no ERROR/MISSING overlaps a graph-relevant capture or causes measured division/paragraph/data-item collapse. A small contained diagnostic may be green only if a pinned policy rule proves it cannot affect extracted semantics. |
| **Amber** | Useful partial tree, human/AI-assisted review warranted | Permit explicitly marked partial indexing only for captures outside affected mapped ranges; write a review-bucket record. | Localized ERROR/MISSING or unresolved include with substantial unaffected structure retained; diagnostics do not invalidate the whole file, but semantic completeness is uncertain. |
| **Red** | Unsafe to trust | Quarantine from normal indexing, retain evidence, and prioritize review. | Timeout/crash/no tree; source-map failure; non-deterministic output; missing essential division/program anchors; ERROR/MISSING overlaps graph-relevant identifiers; severe cascade/retention collapse; unbounded or unresolved transformation provenance. |

**Do not define green as `ERROR count == 0`.** The existing baseline proves low error counts can coexist with catastrophic structural loss. Likewise, do not force every contained ERROR to red; the point of grading is to preserve useful, explicitly bounded partial trees.

## Differentiators

These are not generic parser conveniences. They make the estate-recovery workflow materially safer and more effective than a conventional parse/pass-fail harness.

| Feature | Value proposition | Complexity | Recommendation |
|---------|-------------------|------------|----------------|
| Cascade-aware retained-structure scoring | Measures whether divisions, data items, paragraphs, and graph-relevant captures survive, catching the failure mode raw ERROR counts miss. | High | Build into the first grading policy, not as a later dashboard metric. |
| Mapping-backed diagnostics and captures | Every diagnostic and extracted identifier points to original consolidated source even after continuations/includes/neutralization. | High | Treat as the defining differentiator and gate downstream integration on it. |
| Cluster-first review queue | Presents one recurring defect with affected-program count and representative minimized evidence instead of 300 near-identical files. | High | Make cluster the primary work unit; keep file records as observations. |
| Privacy-preserving AI handoff | Produces useful, provider-neutral packets without network access or raw-source disclosure. | Medium | Export artifacts only. Any provider adapter belongs to a later consumer milestone. |
| Evidence-linked grammar promotion | Connects benchmark cluster → synthetic reproducer → grammar fixture → differential result → cluster reduction. | Medium | Require this lineage for every grammar backlog promotion. |
| Dual-axis progress reporting | Reports parse trust and semantic retention separately. A lower ERROR count is not called an improvement unless retained graph-relevant structure is stable or better. | Medium | Include both axes in every benchmark delta. |
| Versioned regrading without reparsing | Stores normalized diagnostics/retention facts so policy changes can be evaluated separately from parser/preprocessor changes where inputs are sufficient. | Medium | Useful after the initial benchmark; do not overbuild a policy DSL. |
| Stable cluster lineage | Tracks clusters across parser/preprocessor versions as resolved, persistent, split, merged, or newly introduced. | High | Add after deterministic signatures are stable; it makes backlog burn-down credible. |

## Review-Bucket Record Contract

A record should be operational, deduplicable, and safe to export. Recommended minimum fields:

| Group | Fields |
|-------|--------|
| Identity | `schema_version`, stable `record_id`, source content hash, logical source ID hash, parser revision, preprocessor version, grading-policy version, config/include-catalog hash |
| Outcome | grade, ordered reason codes, parser status, timing, diagnostic counts by kind, mapping completeness, retained division/section/paragraph/data-item/capture metrics |
| Evidence | normalized diagnostic signatures, generated and mapped ranges, nearest named-node paths, transformation rule IDs, synthetic/unmapped flags |
| Clustering | signature version, cluster ID, occurrence count, first/last observed benchmark IDs, representative-record flag |
| Workflow | state (`open`, `triaged`, `grammar_candidate`, `preprocessor_candidate`, `invalid_input`, `accepted_degradation`, `resolved`), owner optional, disposition reason, linked backlog/test IDs |
| Privacy | sensitivity classification, minimization version, raw-source-present boolean fixed to false for exportable records, packet eligibility/rejection reasons |

Do not use file paths or filenames as the primary identity. They may change, contain sensitive naming, and fragment identical failures. Keep any local path reference in a non-exported sidecar keyed by hash.

## Clustering Behavior

1. **Normalize without erasing syntax class.** Replace identifiers, literals, sequence numbers, and absolute coordinates with typed placeholders while retaining diagnostic kind, named-node ancestry, COBOL division/section context, nearby keyword classes, and transformation reason.
2. **Separate ownership before clustering.** Preprocessor failures, source-map failures, include resolution failures, parser/grammar gaps, malformed/truncated inputs, and resource failures must not share a cluster merely because all end in an ERROR node.
3. **Prefer deterministic exact signatures first.** Start with exact normalized-signature grouping. Approximate/embedding clustering is out of scope because it is non-deterministic, harder to audit, and risks leaking text.
4. **Rank by impact, not count alone.** Recommended order: red before amber; then affected programs; then retained-structure loss; then graph-relevant overlap; then occurrence count; then reproducibility/minimization readiness.
5. **Preserve outliers.** A singleton red failure is still actionable. Never discard a cluster because it is small.
6. **Version signatures.** Changing token windows or normalization rules must create a new signature version and an explicit lineage/migration report.

## Provider-Neutral Minimized AI Packet

The packet is evidence, not a prompt and not an API request. Recommended top-level contract:

```json
{
  "schema_version": "1",
  "packet_id": "sha256:...",
  "cluster": {
    "signature_version": "1",
    "cluster_id": "sha256:...",
    "grade": "red",
    "affected_programs": 0,
    "occurrences": 0
  },
  "toolchain": {
    "parser_revision": "...",
    "preprocessor_version": "...",
    "grading_policy_version": "..."
  },
  "evidence": {
    "reason_codes": [],
    "normalized_diagnostics": [],
    "retained_structure": {},
    "transformations": [],
    "mapped_ranges": []
  },
  "reproducer": {
    "kind": "synthetic|redacted|none",
    "content": null,
    "derivation": "hand_written|token_class_minimized|unavailable"
  },
  "constraints": {
    "raw_source_included": false,
    "external_call_permitted": false
  }
}
```

Rules:

- Deterministic key ordering and packet hash.
- No chat roles, model name, temperature, vendor endpoint, tool schema, or credentials.
- No raw file path, member name, comments, literals, business identifiers, or unbounded source windows by default.
- Prefer hand-written synthetic reproduction. If safe minimization cannot preserve the failure, emit `none` plus structural facts rather than weakening privacy.
- Include enough source-map provenance to explain location transformations, but never include the underlying proprietary span in the exportable packet.
- Enforce a bounded packet size; reference local evidence by content hash rather than embedding it.

## Corpus Benchmark Behavior

The benchmark is a product feature, not a one-off script.

### Required invariants

- Manifest identifies exactly 1,369 compilable programs and has a stable membership digest.
- No silent skip. Every manifest entry ends as processed, timeout, I/O failure, preprocessing failure, mapping failure, or parser failure.
- Inputs are read-only; outputs go to controlled scratch/aggregate locations.
- Toolchain revisions, configuration, include-catalog digest, grade-policy version, signature version, host-independent options, and timing method are recorded.
- Per-program raw diagnostics stay local. Repository-safe benchmark artifacts contain only aggregate counts, hashes, normalized signatures, and synthetic evidence.
- Repeated same-version runs are reconciled before any candidate delta is accepted.

### Required report slices

| Slice | Metrics |
|-------|---------|
| Population | declared members, 1,369-program denominator, processed/missing/failed reconciliation |
| Preprocessing | programs/lines transformed by rule, include resolved/missing/cyclic, continuation joins, deterministic-output mismatches |
| Mapping | total segments, unmapped/synthetic diagnostics, mapping failures, round-trip test status |
| Parse quality | green/amber/red counts and percentages, reason-code counts, ERROR/MISSING counts, timeouts/crashes |
| Retention | programs/divisions/sections/data items/paragraphs and graph-relevant captures retained; distribution, not only totals |
| Review | distinct records, clusters, affected programs per cluster, singleton count, packet eligibility/rejection |
| Performance | stage duration distributions and bounded resource failures |
| Differential | every grade transition; new/resolved/persistent clusters; retained-structure gains/losses; no-regression verdict |

The benchmark should retain the current parser's aggregate diagnostics as the pre-v0.26 baseline but must not pretend existing SQL, CICS, or ACCEPT differentials are a complete 1,369-program quality baseline. They prove specific collision and extraction properties. The first full grade distribution will be established by this milestone's pinned benchmark.

## Evidence-Driven Grammar Backlog

Each benchmark cluster must first be classified into one owner:

1. **Preprocessor rule defect** -- transformation is wrong, incomplete, non-deterministic, or loses provenance.
2. **Source-map defect** -- parsing may be correct, but coordinates cannot be trusted.
3. **Include/catalog issue** -- source is incomplete because dependency resolution failed.
4. **Generic grammar gap** -- valid dialect syntax remains unsupported after correct preprocessing.
5. **Malformed/truncated source** -- no generic parser change is justified.
6. **Accepted contained degradation** -- amber behavior is bounded and lower priority than other clusters.
7. **Infrastructure/resource failure** -- timeout, crash, or I/O issue.

A grammar backlog item is promotable only when it has:

- A stable cluster signature and affected-program count from the 1,369 denominator.
- Evidence that preprocessing and mapping are correct for the case.
- Retained-structure or graph-relevant impact, not merely an ERROR-count reduction.
- A minimal hand-written synthetic fixture or a documented reason it cannot yet be produced.
- A generic dialect rationale, not a site-specific name or one-file patch.
- Planned corpus/NIST/differential/cascade gates and expected benchmark movement.
- A clear stop condition. Long thin tails with no concentration remain backlog evidence, not automatic grammar scope.

Recommended ranking formula is lexicographic rather than a fragile weighted score:

1. Red clusters that overlap graph-relevant captures or destroy a division.
2. Other red clusters by affected-program count and retention loss.
3. Amber clusters by affected-program count and graph incompleteness.
4. Within ties, reproducible clusters with a safe synthetic fixture first.

## Anti-Features

| Anti-feature | Why avoid | Do instead |
|--------------|-----------|------------|
| External model invocation in this milestone | Violates offline-by-default scope and creates provider/privacy coupling before evidence contracts are stable. | Export validated provider-neutral packets only. |
| Raw estate source in review records, packets, tests, logs, commits, or benchmark reports | Proprietary data would cross the public-repository or provider boundary. | Use hashes, normalized signatures, mapped coordinates, aggregate counts, and hand-written synthetic fixtures. |
| Destructive in-place preprocessing | Breaks provenance and risks mutating the source of truth. | Read-only input plus separate transformed output and map. |
| Regex-only global rewriting | Ignores fixed-format columns, comments, literals, continuations, and near-miss syntax. | Ordered, column-aware recognizers with explicit rule IDs and fixtures. |
| Silent include fallback or fuzzy member matching | Produces plausible but wrong programs and non-reproducible graphs. | Explicit catalog, exact resolution, missing/cycle diagnostics. |
| Line-only or delta-only source maps | Cannot faithfully map continuations, replacements, insertions, multibyte text, or include expansion. | Segment-level byte/range provenance with defined point bias. |
| Grade from process exit status or ERROR count alone | Existing diagnostics prove both are poor proxies for retained semantic structure. | Combine hard failures, mapped diagnostics, retained anchors, and graph-relevant overlap. |
| Automatic green indexing of all partial trees | Silently converts parser recovery into trusted graph facts. | Grade first; constrain amber indexing; quarantine red. |
| Blanket red for any ERROR node | Throws away useful bounded partial trees and defeats triage. | Use containment and retained-structure semantics. |
| Filename/path-based deduplication | Leaks naming and treats recurring grammar gaps as separate incidents. | Content/config hashes and normalized structural cluster signatures. |
| Embedding/LLM-based clustering | Non-deterministic, difficult to audit, provider-coupled, and likely to expose text. | Deterministic exact normalized signatures for v0.26.0. |
| Auto-applying AI grammar patches | Removes human review and regression proof from a safety-critical parser surface. | AI packet may inform review; grammar changes still require synthetic fixtures and all gates. |
| Tuning thresholds to make the benchmark look green | Converts measurement into theater and hides regressions. | Freeze policy version before candidate comparison; report transitions and calibrations explicitly. |
| ERROR-node elimination as the success metric | Neutralization can remove cascades while destroying graph content. | Measure graph-relevant captures and retained structure. |
| Broadening the grammar for every singleton | Creates ambiguity and regressions without meaningful estate impact. | Promote only evidence-supported generic clusters; retain long-tail evidence. |
| Replacing existing regression harnesses | Duplicates trusted infrastructure and fragments evidence. | Extend the current corpus, NIST, differential, query, cascade, shim, and estate-guard gates. |
| Full SQL grammar, alternative parser adoption, or `EXEC DLI` support | Already deferred/rejected or has zero measured estate demand. | Keep bounded SQL extraction, current parser lineage, and measured backlog scope. |
| General site-macro language implementation | It is not COBOL and would expand this milestone into a separate language processor. | Limit preprocessing to the named deterministic constructs. |
| IDE/UI/dashboard work | Does not advance source fidelity, grading, review evidence, or grammar recovery. | Emit stable machine-readable records; build presentation later if needed. |

## Scope Boundaries

### In scope for v0.26.0

- A standalone top-level Go `preprocessor/` module, isolated from the forest shim's parser API.
- Deterministic handling of fixed-format source, continuations, Endevor `-INC`, and named IDMS structural lines.
- Reversible generated-to-original source mapping and transformation provenance.
- Parse diagnostics, retention metrics, and a versioned green/amber/red policy.
- Durable amber/red review records and deterministic exact-signature clustering.
- Offline, provider-neutral minimized packet export with no raw estate source.
- A pinned, reconciled 1,369-program benchmark and same-manifest differential.
- Ranked backlog generation and a small number of high-impact, generic, regression-tested grammar fixes justified by benchmark evidence.

### Explicitly out of scope

- Calling OpenAI, Anthropic, Azure OpenAI, local model servers, or any other model provider.
- Prompt orchestration, agent loops, RAG, vector databases, embeddings, or provider adapters.
- Raw-source review UI, web service, multi-user workflow, ticketing integration, or notification delivery.
- Compiling or executing COBOL; semantic/type/data-flow validation beyond parse-retention evidence.
- Reconstructing the complete Endevor build environment or implementing arbitrary site macros.
- Fetching includes from remote systems; the preprocessor consumes an explicit local catalog.
- A universal COBOL preprocessor, full conditional-compilation system, full DB2 SQL grammar, or alternate parser.
- Automatic grammar mutation, automatic PR creation, or unsupervised acceptance of AI suggestions.
- Using proprietary source as fixtures or retaining it in repository artifacts.
- Re-baselining away regressions, expanding the NIST skip list, or changing the 1,369 denominator without an explicit manifest-version decision.

## Feature Dependencies

```text
Immutable input manifest + deterministic configuration
  -> fixed-format normalization
  -> continuation/include/IDMS transformations
  -> transformation ledger + reversible source map
  -> Tree-sitter parse
  -> mapped diagnostics + retained-structure metrics
  -> versioned green/amber/red grade
  -> review-bucket record
  -> deterministic cluster
  -> minimized provider-neutral packet
  -> benchmark differential
  -> evidence-driven owner classification
  -> prioritized grammar/preprocessor backlog
  -> synthetic fixtures + implementation + regression gates
  -> benchmark rerun and cluster/grade transition proof
```

Critical ordering constraints:

- Source-map correctness must precede trusted diagnostics, grades, and review packets.
- The grading policy and benchmark manifest must be versioned before claiming before/after improvement.
- Review records precede clustering; clustering precedes packet generation and backlog ranking.
- Grammar fixes come after the preprocessing benchmark exposes residual clusters, not before.

## MVP Recommendation and Roadmap Slices

1. **Deterministic preprocessing core**
   - Fixed-format model, continuation handling, explicit include catalog, IDMS structural transforms.
   - Transformation ledger and byte-accurate reversible source map.
   - Synthetic and property tests; no estate-derived fixtures.

2. **Quality facts and grading**
   - Tree walk for ERROR/MISSING, mapped diagnostics, retained divisions/data items/paragraphs/captures.
   - Green/amber/red hard semantics with versioned reason codes.
   - Calibrate only numeric amber/red thresholds on aggregate benchmark evidence.

3. **Secure review records and clustering**
   - Idempotent records, lifecycle states, exact normalized signatures, impact ranking.
   - Privacy/path containment tests before any packet export.

4. **Provider-neutral packet export**
   - Stable JSON Schema, deterministic hash/serialization, bounded synthetic/redacted evidence.
   - No external calls and no provider-shaped fields.

5. **Pinned 1,369-program benchmark**
   - Manifest reconciliation, aggregate baseline, repeatability check, stage timings, grade/retention/cluster distributions.
   - Same-manifest differential becomes a required gate.

6. **Evidence-driven recovery loop**
   - Classify top clusters by owner.
   - Fix preprocessing defects first, then promote only high-impact generic grammar gaps with hand-written fixtures.
   - Rerun benchmark and require favorable grade/retention transitions without existing corpus/NIST/differential regressions.

**Defer:** approximate clustering, model invocation, dashboards, full SQL parsing, generalized macro processing, and low-volume grammar tails. They add cost or risk before the deterministic evidence chain is proven.

## Current Diagnostic Baseline to Preserve

These are known measured anchors, not a complete v0.26 grading baseline:

- Population: 3,781 declared COBOL members, **1,369 compilable programs**.
- Historical recall: 606 `.cbl` plus 958 `.cpy`; grammar-alone `.cbl` data items 17,905 versus 32,360 after destructive neutralization; grammar-alone `.cpy` data items 0 versus 22,800 after neutralization.
- Retention/cascade evidence: one unsupported CICS construct previously left 1/20 following paragraphs; one IDMS structural construct left 0/20 data items; one large program had four ERROR nodes but retained only 5/77 paragraphs.
- Current post-grammar paragraph recovery on the DCC corpus: Phase 1 9,187, Phase 2 15,323, Phase 3 18,234, exceeding the 16,732 terminal comparison.
- Current IDMS residual-tail census: 119 down to 9 after evidence-led grammar work.
- Current CICS residual tail: zero on measured DCC and estate populations, with one disclosed contained comma-bearing edge family at 4 of 7,971 arguments.
- Current SQL differential: estate denominator 1,369; 1,201 selected files; 9,871 baseline records versus 10,115 current; 244 new, zero reclassified/converted, zero timeouts. This is collision/extraction evidence, not an overall parse-grade distribution.
- Current regression floor: 149 non-comment corpus assertions pass; NIST reports 371 success, 0 failure, 11 known skips. The separate legacy `comment` fixture remains an open, pre-existing diagnostic and must not be hidden by benchmark reporting.
- Current tooling diagnostic: no JavaScript LSP provider is configured for `grammar.js`; executable generation, corpus, query, differential, and NIST gates remain the authoritative checks for that surface.

The first v0.26 benchmark must establish the missing full-population values: green/amber/red distribution, mapped ERROR/MISSING distribution, source-map completeness, retained-structure distribution, review-cluster inventory, and preprocessing-rule prevalence.
