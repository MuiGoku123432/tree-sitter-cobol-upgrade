<objective>
Write the regenerate-and-refresh sequence as a shell script inside the shim directory, execute it
repeatedly to prove it is reproducible, and prove end-to-end that a change made in `grammar.js`
reaches gortex's parse output through it.

Purpose: VEND-04 is the requirement that makes phases 2-4 cheap. Without a scripted sequence, every
grammar change is a hand-assembled copy that will eventually be done wrong — and RESEARCH.md proved
the non-obvious part experimentally: flattening `parser.h` out of its subdirectory is necessary but
not sufficient, because the copied `parser.c` and `scanner.c` still ask for the old path, in two
different include syntaxes.

Output: `forest-shim/refresh.sh`, a refreshed shim, and a recorded propagation proof.

Note on the phase boundary: CONTEXT.md `<domain>` states there are **no grammar changes in this
phase**. Task 3's probe edit is transient — uncommitted, reverted in the same task, with a
clean-tree assertion — exactly the same shape as the isolated tree-sitter-cli spike CONTEXT.md
already sanctions. Nothing about the committed grammar changes; the fork stays level with
`upstream/main` on grammar content. Because "reverted in the same task" is only worth as much as
the weakest run that reaches the revert, the probe owns its edit window as a script with the revert
registered as a trap on EXIT, INT and TERM — the same failsafe shape plan 02's
`estate-guard-selftest.sh` uses for its scratch directory — so a build failure, a timeout or a
killed agent still leaves the tree clean.
</objective>

Write `forest-shim/refresh.sh`. Shebang `#!/bin/bash`, matching `test/check_tests.sh` — the one
script in this repo that declares one, and the closer analog in spirit (a maintenance tool, not a
CI pass/fail gate). Use this repo's house style throughout: explicit `$?` checks after each command
that can fail, never the abort-on-error or unset-variable shell options (no script here uses
either), integer counters, `tee`-style dual reporting to stdout and to `$REFRESH_LOG`, and a single
aggregate exit code at the end derived from the failure counter rather than from the last command.

It is deliberately NOT an npm script (D-07): adding an entry to `package.json` would edit an
upstream-owned file that dependabot keeps moving — including the very CLI bump plan 04 measures —
which makes it the worst possible place to put a fork-local entry. It is deliberately not a
Makefile either: this repo uses no make anywhere.

Resolve its own directory first and derive paths from that, so the script works regardless of the
caller's working directory (matching `check_tests.sh`'s relative-directory convention without
inheriting its assumption of being `cd`'d into first). Expose these overridable variables, each
defaulted with the `${VAR:-default}` form:
- `TOP_DIR` — the repo root, derived from the script's own location.
- `SHIM_DIR` — `$TOP_DIR/forest-shim/cobol`.
- `TREE_SITTER` — `$TOP_DIR/node_modules/.bin/tree-sitter`, the same relative-path variable
  `run_nist_cobol85.sh` uses. Overridable so the exit-code discipline can be fault-injected.
- `FOREST_CACHE` — `$(go env GOMODCACHE)/github.com/alexaandru/go-sitter-forest/cobol@v1.9.1`.
- `REFRESH_LOG` — `$TOP_DIR/forest-shim/refresh.log`.
- `REFRESH_SKIP_INSTALL`, `REFRESH_SKIP_GENERATE`, `REFRESH_ALLOW_DRIFT` — empty by default.

`$TOP_DIR`. Then report — as an informational result line, not a failure — whether

**Part A — write `forest-shim/pipe-probe.sh`.** Same house style as `refresh.sh`: shebang

script's own location; `GORTEX_DIR` defaulting to `~/repos/mine/GoApps/gortex`; `PROBE_CAPTURE_DIR`

`go test -run 'TestDumpGrammarKinds/cobol' -v ./internal/parser/forest/` and save stdout to
