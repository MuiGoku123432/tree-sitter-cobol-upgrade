<objective>
Make the estate-leak guard's self-test able to tell a working guard from a broken one, and prove
it can — by requiring it to FAIL against the guard as currently shipped.

This is the RED half of a deliberate red-then-green sequence. Plan 01-07 is the GREEN half.

The reason FORK-02 shipped with four Critical false-negative paths and a green light is CR-05:
`report_case()` asserts only that the guard exited non-zero. A guard replaced by a two-line
stand-in performing zero checks passes all four polluted cases. The proof did not constrain the
thing it claimed to prove. So the guard's defects are fixed SECOND, not first — if the guard were
repaired first and the test strengthened afterwards, nothing would ever demonstrate that the test
can now catch these defects, and we would be re-running the same unfalsifiable proof that already
failed once.

Purpose: turn 01-REVIEW.md's four manual reproductions into permanent, scripted regression cases,
and turn the CR-05 stand-in reproduction into a re-runnable assertion.
Output: a strengthened `.githooks/estate-guard-selftest.sh` plus a recorded transcript of it
failing against the unfixed guard.

**An executor MUST NOT collapse this plan into 01-07.** The guard is not touched here. If the
suite goes green at the end of this plan, this plan has failed its purpose and Task 3's gate
blocks.
</objective>

| ESTATE_GUARD_PATH → guard resolution | An environment-controlled path selects which binary is exercised |
