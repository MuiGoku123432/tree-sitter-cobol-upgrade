## Decision-fidelity note on D-18

D-18 specifies the self-test creates "two throwaway branches — one deliberately polluted, one
clean". This plan implements exactly that fail-then-pass proof, but the throwaway branches live in
a scratch repository under `$(mktemp -d)` rather than in this fork. Reason: a branch in *this* fork
carrying an `estate/` path would create precisely the git object this guard exists to prevent — the
blob survives branch deletion until `gc`, and one mispush would publish it. The scratch-repo form
is the same proof, is re-runnable, additionally lets the self-test prove the `.git/info/exclude`
check FAILS when the exclusion is absent (impossible to test against the real repo without
breaking it), and leaves zero residue here.
</flagged_assumptions>

Write `.githooks/estate-guard.sh`, a POSIX-ish shell script matching this repo's house style.

**House style (from `run_nist_cobol85.sh`):** explicit `$?` checks after each command that can
fail; never introduce the abort-on-error or the unset-variable shell options — no script in this
repo uses either, and doing so here would be the first. Accumulate a `FAIL_COUNTER` and a
`CHECKS_RUN` counter in plain integer variables, report every result line through `tee`-style dual
output (stdout plus an optional log path), and end with an aggregate exit code derived from
`FAIL_COUNTER`, not from the last command run. Quote every path expansion, and never hand
diff-derived content back to the shell for re-interpretation as a command.

**Modes.** Accept exactly these invocations:
- `--check-exclude` — run check 2 only.
- `--range <A>..<B>` — run all three checks over that commit range.
- `--staged` — run all three checks over `git diff --cached`.
- no arguments — read git's `pre-push` stdin protocol, one line per ref update with the fields
  `<local ref> <local sha> <remote ref> <remote sha>`, and run all three checks over each update.

**stdin ref-update handling.** A remote sha of all zeros means a new branch: bound the range with
`--not --remotes` so the guard scans only what is genuinely new, not the entire history. A local
sha of all zeros means a branch deletion: nothing is being pushed, so skip the range checks for
that line but still run check 2. Zero ref-update lines on stdin is a valid, non-error case.

**Check 1 — reject any `estate/` path.** Over the range (or the staged set), list changed paths
with `git diff --name-only` in its range form and fail if any path is under the excluded
proprietary working-copy directory at the repo root. Match on the path prefix anchored at the start
of the path string, so an unrelated file whose name merely contains that word is not flagged.

**Check 2 — assert the exclusion posture.** `.git/info/exclude` must still declare the proprietary
working-copy directory, and `.gitignore` must not declare it. This split is deliberate: the
exclusion lives in the repo-local exclude file so the upstream diff stays at zero. Fail if either
half is wrong. This check runs on EVERY invocation, including when the range is empty — an empty
change must never produce a pass that checked nothing.

**Check 3 — sequence-area heuristic on diff-ADDED lines only.** Take `git diff` over the range
restricted to COBOL-ish paths, keep only lines that begin with a single `+` (excluding the `+++`
file header), and inspect bytes 73-80 of the line content. Fail if any of those eight bytes is
non-blank.

Pin the file scope in one greppable variable named `COBOL_PATH_RE`, matching: any path ending in a
COBOL source or copybook extension in either case (`cbl`, `CBL`, `cpy`, `CPY`, `cob`, `COB`), any
path under `test/corpus/`, and any path under `test/cobol85/`. Markdown and prose files are
deliberately out of scope for this check because `docs/` lines legitimately run past 73 characters;
the prohibition on quoting estate content into docs is enforced by review, not by this heuristic.

Pin the column semantics explicitly, and say so in a comment at the check site so a later editor
cannot quietly change them:
- Columns 73-80 means **bytes** 73-80 of the line content, after the leading `+` is stripped. Run
  the extraction under `LC_ALL=C` so `awk`'s `substr` is byte-indexed rather than character-indexed.
  Define `SEQ_AREA_FIRST_BYTE=74` for the offset into the raw `+`-prefixed diff line and derive the
  guard condition from it, so the two never drift apart.
- A line whose content is shorter than 73 bytes has no sequence area and is never flagged.
- A tab is one byte and is NOT expanded to a tab stop — this is a fixed-format byte-column rule, not
  a display-column rule.
- A UTF-8 multibyte character counts as its byte length, not as one code point and not as one
  display column.

Comment at the same site that this check is scoped to diff-added lines on purpose: the NIST
fixtures under `test/cobol85/src/*.CBL` are public, upstream-owned, 80-column fixed-format files
that legitimately carry a populated sequence area, and re-scanning whole files would false-positive
on every one of them. That comment is the durable warning against a later "simplification".

**Reporting.** One line per check per invocation naming the check and its verdict, so a reader can
see all three ran. End with a single summary line and exit 0 only when `FAIL_COUNTER` is zero.
  </action>

**Base state of the scratch repo.** Write `/estate/` into its `.git/info/exclude`, leave its

fixed-format file at `test/cobol85/src/PROBE01.CBL` whose lines carry a populated columns 73-80
sequence area — a synthetic stand-in for a NIST fixture, hand-written, never copied from `estate/`
or from any real NIST file.

**Polluted cases — each must make the guard exit non-zero:**
1. A throwaway branch whose commit adds a file under an `estate/` path.
2. A throwaway branch whose commit adds a `.cpy` file whose lines carry a populated columns 73-80
   sequence area.
3. The exclusion line removed from the scratch repo's `.git/info/exclude`, checked with
   `--check-exclude`.
4. The exclusion line present in `.git/info/exclude` but ALSO declared in the scratch repo's
   `.gitignore`, checked with `--check-exclude` — the split D-16 asserts is directional, and both
   halves must have teeth.

**Clean cases — each must make the guard exit zero:**
5. A throwaway branch whose commit adds a hand-written minimal COBOL fixture with short lines (no
   line reaching 73 bytes), mirroring `test/corpus/minimal-cobol.txt`'s 36-character maximum.
6. An empty range: a branch with no new commits relative to its base. The guard must exit 0 AND its
   output must still contain the exclusion-check result line, proving the pass was not vacuous.
7. An empty commit (`--allow-empty`), i.e. a push with zero added lines. Same two assertions.
8. **The NIST false-positive regression case:** a commit that modifies an unrelated short-line file
   while `test/cobol85/src/PROBE01.CBL` — already committed in the base state, populated sequence
   area and all — sits untouched in the tree. The guard must exit 0. This is the case that fails
   loudly if the sequence-area check is ever "simplified" from diff-added lines to a full-file scan.
9. Encoding cases, all clean: a line whose content is exactly 72 bytes; a line containing a tab in
   the code area whose content is under 73 bytes (the tab must not be expanded to a tab stop and
   push content into the sequence area); and a line containing a UTF-8 multibyte character with
   fewer than 73 bytes of content. None may be flagged.

**Reporting and exit code.** Print one PASS/FAIL line per numbered case, accumulate a return code
across the whole run, and exit with it at the end rather than exiting early — matching
`test/check_tests.sh`'s convention. Finish by running the real guard against this fork's live
state (`--check-exclude`, and `--range HEAD~1..HEAD`) and asserting both pass, so the self-test
covers the real repository as well as the synthetic one.

**Part A — `.githooks/commit-separability.sh` (FORK-03).** For each commit in a ref range (default
range: commits on `HEAD` that are not on `upstream/main`), read its changed paths with
`git show --stat --name-only --pretty=format: <sha>` and fail the commit if its path set intersects
BOTH families:
- `GRAMMAR_PATH_RE` — `grammar.js`, anything under `test/corpus/`, and anything under `src/`
  (`src/` is regenerated output of `grammar.js`, so it belongs to the grammar family).
- `FORKLOCAL_PATH_RE` — anything under `forest-shim/`, `docs/`, `.planning/`, or `.githooks/`.

guard: explicit `$?` checks, no abort-on-error or unset-variable shell options, a counter, one
report line per offending commit naming the two colliding paths, and an aggregate exit code.

Accept `--range <A>..<B>` and a bare invocation. If `upstream/main` cannot be resolved (a clone
without the upstream remote), report that explicitly and check `HEAD~20..HEAD` instead — never
silently check nothing.

**Part B — `.githooks/pre-push`.** A `#!/bin/bash` script that reads git's stdin ref-update protocol
once, tees it to both guards, and exits non-zero if either fails. Concretely: capture stdin into a
variable, feed it to `.githooks/estate-guard.sh` in its default stdin mode, then compute the same
ranges and run `.githooks/commit-separability.sh --range` over each. Resolve the sibling scripts
relative to the hook's own directory rather than assuming the process working directory, and make
all four `.githooks/` files executable (`chmod +x`).

Print a one-line banner naming which guards ran, so a developer watching a push can see the checks
fired rather than inferring it from silence.

**Part C — install.** Run `git config core.hooksPath .githooks` in this fork. This is D-17's
"one-line install step", and it is chosen over copying a script into `.git/hooks/pre-push` for the
same reason D-17 chose `pre-push` over CI: `.git/hooks/` is never tracked by git, so a hook living
there cannot be reviewed, cannot be diffed across commits, and silently fails to reach a fresh
clone. Verify with `git config --get core.hooksPath`. Do not delete or modify the stock
`.git/hooks/*.sample` files.

**Part D — record the residual limitation.** `git push --no-verify` bypasses any client-side hook by
git's own design, and no server-side backstop is in scope for this phase. State this in a comment
at the top of `.githooks/pre-push`; plan 04 carries the same statement into `docs/vendoring.md` so
a future reader does not assume the guard is unbypassable.

Commit all four scripts as a single fork-local commit. Per D-12, do not mix them with any
`grammar.js` or `test/corpus/*` change — and note that this commit is itself the first thing the new
separability check will be run against.
