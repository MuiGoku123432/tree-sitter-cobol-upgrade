<flagged_assumptions>
- **`BIND` is not one shape (02-RESEARCH.md Pitfall 4, Open Question 1).** The CA IDMS manual
  documents both `BIND RUN-UNIT` (argument-free, session-establishing) and `BIND RECORD` /
  `BIND record-name` (record-name-bearing, normally auto-generated by `COPY IDMS SUBSCHEMA-BINDS`).
  The estate's raw counts — 4,631 estate-wide, 299 of 606 DCC `.cbl` files — do **not** distinguish
  which form dominates. This plan models both rather than assuming the argument-free shape, and
  leaves the volume question to 02-06's `idms_unparsed_tail` census. Unresolved: whether hand-typed
  `BIND RECORD` occurs at meaningful volume at all.

- **`idms_unparsed_tail` token set remains provisional (RESEARCH A1/A3).** 02-01 fixed a leaf-token
  set from first principles with no in-repo analog. Every new operand shape this plan adds is a
  fresh chance for a token that does not lex as one of those leaves, which would surface as an
  ERROR rather than a tail. The acceptance criteria make that observable per fixture.
</flagged_assumptions>
