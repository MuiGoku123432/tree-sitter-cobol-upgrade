  <action>
    Create `run_accept_differential.sh` at the repo root — fork-local per D-08, matching
    `run_nist_cobol85.sh`'s placement and shell house style: no shell-level abort-on-error or
    abort-on-unset options anywhere (this repo uses none), explicit `$?` checks after every command
    that can fail, integer counters, a `tee`'d summary line, and an exit code driven by the counter
    rather than by the last command run.

    Give it three sub-commands.

    `snapshot <CORPUS_DIR> <OUT_FILE> [NODE_TYPE_REGEX]` walks every `*.cbl`/`*.CBL` under
    `CORPUS_DIR`, runs `$TREE_SITTER parse` on each, and writes one tab-separated inventory record
    per matching node: relative path, `startRow,startCol`, node type, and a **cleanliness
    qualifier** of `clean` or `trailing_error`. `NODE_TYPE_REGEX` defaults to
    `accept_statement|idms_accept_statement`, which is the only set `compare` reasons about. The
    argument exists so plan 02-06 can produce its `idms_unparsed_tail` census with this same tool
    rather than standing up a second corpus-scanning harness, which PROJECT.md forbids. Output is
    sorted so `compare` is a stable join. Count and report files that failed to parse separately
    from files with zero matches — a parse failure is not the same as an absence, and conflating
    them is how a differential silently shrinks its own denominator.

    The cleanliness qualifier is load-bearing and is the reason this gate is satisfiable at all.
    Today, before any grammar change, an IDMS `ACCEPT WS-DB-KEY FROM CUSTOMER-REC CURRENCY.` already
    matches the existing `_accept_body` rule through `FROM CUSTOMER-REC` and leaves the trailing
    `CURRENCY` to an ERROR node — so all ~634 IDMS occurrences are `accept_statement` nodes in the
    before-inventory. After 02-04 they become `idms_accept_statement`. Without the qualifier those
    634 legitimate conversions are indistinguishable from a real reclassification of standard COBOL,
    and D-07's zero-tolerance gate would be unsatisfiable by construction. Derive the qualifier from
    `tree-sitter parse`'s own printed tree: mark a record `trailing_error` when an `(ERROR` node
    begins on the same source row on which the `accept_statement` node ends, `clean` otherwise.
    State that same-row heuristic in the script's header comment — it rests on IDMS DML being
    written one statement per line, which is the same assumption gortex's `reDML` regex
    (`[^.]*\.`) already relies on successfully across all 606 DCC `.cbl` files.

    `compare <BEFORE_FILE> <AFTER_FILE>` joins on `path + position` and reports: total before- and
    after-records, `accept_statement` and `idms_accept_statement` counts in each, and the before
    `clean` / `trailing_error` split. It then computes two separate tallies. RECLASSIFIED — records
    whose before-type is `accept_statement` with a `clean` qualifier and whose after-type is
    anything other than `accept_statement`, including absent — prints each offending record and
    drives the exit code: `compare` exits 1 if RECLASSIFIED is greater than zero. CONVERTED —
    records whose before-type is `accept_statement` with a `trailing_error` qualifier and whose
    after-type is `idms_accept_statement` — is reported as a count and does NOT fail the gate; it is
    the number D-07 expects to land near 634 on the estate. A record present only in the
    after-inventory is NEW, and is neither. When both inventories are empty the summary states that
    zero records were compared, rather than emitting a bare PASS.

    `run <BASELINE_REF> <CORPUS_DIR>` orchestrates the two: it creates a throwaway `git worktree`
    at `BASELINE_REF` under `$DIFF_TMP`, symlinks this repo's `node_modules` into it so the pinned
    CLI is available, runs `tree-sitter generate` there, snapshots the corpus with the baseline
    parser, snapshots it again from the main working tree with the current parser, runs `compare`,
    and removes the worktree. This shape is what makes the differ re-runnable for Phases 3 and 4
    and after any upstream pull, rather than depending on a snapshot captured at one moment.

    Add a hard estate guard inside the script: `DIFF_TMP` defaults to a `mktemp -d` outside the
    repository, and `snapshot` refuses to write `OUT_FILE` if its resolved absolute path is under
    the repository root. Inventory records contain corpus file paths, and the corpus of record and
    the estate are both proprietary — an inventory that lands inside the working tree is one
    `git add -A` away from a public repository. The script must also never read corpus *content*
    into itself; it only passes paths to the CLI, exactly as `run_nist_cobol85.sh` does with
    `test/cobol85/src`.

    Do NOT wire this script into `pre-push`. D-08 rejected that explicitly on cost: a full estate
    parse is far too slow for that choke point, and a sampled gate would be a weaker guarantee than
    the manual full run. It is invoked manually at the end of each verb family's work.

    Create `run_accept_differential_selftest.sh` beside it, following
    `.githooks/estate-guard-selftest.sh`'s shape: one report line per case naming which case ran
    and whether the expected exit code was observed, an aggregate FAIL counter, and a
    counter-driven exit code. It writes its inventory fixtures to `$TMPDIR` with a heredoc — no
    tracked fixture files, no corpus, no grammar dependency, so it runs in under a second.
