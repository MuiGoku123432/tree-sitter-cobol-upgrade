# Roadmap: tree-sitter-cobol-upgrade -- v0.26.0 Estate Parse Recovery

## Overview

v0.26.0 adds a deterministic, source-mapped parse-recovery pipeline around the existing COBOL grammar and unchanged forest-shim API boundary. Work proceeds from contracts and corpus controls through byte-first provenance, narrowly scoped fixed-format transforms, auditable parse grading, secure offline review evidence, a complete 1,369-program benchmark, and only then evidence-selected recovery fixes. The ordering is tracer-first: each phase closes an observable end-to-end capability before the next phase depends on it. No phase introduces production Gortex adoption, external AI/model/network calls, UI, arbitrary recursive COPY expansion, or a generalized site-macro engine.

## Historical Reference

Phases 1-4 delivered the prior nodes-for-edges work: the local grammar delivery pipe and measurement baseline, IDMS DML nodes, `EXEC CICS` nodes, and bounded `EXEC SQL` nodes. Formal v0.25.0 archive/tag closeout was intentionally skipped by user choice. Their artifacts remain unchanged under `.planning/phases/01-*` through `.planning/phases/04-*`; this roadmap makes only v0.26.0 Phases 5-11 active.

- [ ] **Phase 11: Evidence-Driven Parse Recovery** - Classify residual ownership and promote only reproduced, high-impact fixes that improve development and holdout evidence without regression

## Phase Details

### Phase 5: Pipeline Contract & Corpus Controls

**Goal**: Users can run a safe, deterministic pipeline shell over the authoritative corpus without changing source files, the forest shim, or the benchmark population.
**Depends on**: Phase 4 (historical parser capability)
**Requirements**: FOUND-01, FOUND-02, FOUND-03, BENCH-01
**Success Criteria** (what must be TRUE):
  1. The top-level `preprocessor/` Go 1.23 module builds and can invoke the existing forest-compatible COBOL parser while the shim's module identity, generated artifacts, and public API remain unchanged.
  2. A run reads original source without mutation or buffer aliasing and either writes all canonical artifacts atomically with restrictive permissions to an approved external root or rejects the root, including repository, corpus, and symlink-escape cases.
  3. The frozen manifest visibly reconciles exactly 3,781 declared COBOL members and exactly 1,369 compilable programs, gives each program exactly one outcome slot, and fails closed if membership, digest, or denominator is incomplete.
  4. Repeating the contract-level run with the same bytes, versions, configuration, and membership yields byte-identical identities and canonical JSON regardless of discovery or worker order; timing remains outside canonical identity.

### Phase 6: Reversible Source-Map Core

**Goal**: Users and downstream stages can project any generated location back to honest original provenance, and invert that relationship, without guessed coordinates.
**Depends on**: Phase 5
**Requirements**: MAP-01, MAP-02, MAP-03
**Success Criteria** (what must be TRUE):
  1. Every generated byte and boundary resolves to exact original pieces or an explicit synthetic anchor, with zero-based byte ranges and byte-derived row/column coordinates for both original and generated content.
  2. Generated-to-original and original-to-generated lookups honestly represent copied, rewritten, inserted, deleted, continuation-joined, and one-to-many origins, including explicit no-image and boundary-bias results.
  3. Validation rejects any map with a coverage gap, overlap, out-of-range span, inconsistent hash/size, false exactness, or nondeterministic composition before it can be persisted or consumed.
  4. Unit, property, and fuzz verification demonstrates exact copied-byte round trips and deterministic valid composition across line endings, fixed-format boundaries, arbitrary bytes, and zero-width boundaries.
**Plans**: TBD

### Phase 7: Fixed-Format Transformation Pipeline

**Goal**: Users can transform raw consolidated COBOL into parser-ready bytes while preserving fixed-format meaning, graph-bearing constructs, and a complete explanation of every edit.
**Depends on**: Phase 6
**Requirements**: PREP-01, PREP-02, PREP-03, PREP-04
**Success Criteria** (what must be TRUE):
  1. Fixed-format inputs preserve the distinct meaning and provenance of columns 1-6, column 7, columns 8-72, and columns 73-80 across comments, short lines, tabs, UTF-8, CRLF/LF, missing final newlines, and true continuations without implicit trimming.
  2. Exact code-area `-INC <MEMBER>` directives become parser-legible `COPY <MEMBER>.` output, while comments, literals, near misses, unresolved members, and cycles remain unguessed and produce explicit diagnostics.
  3. Only the four authorized IDMS structural forms are neutralized; IDMS DML, CICS, SQL, standard COBOL, and their graph-bearing operands remain byte-for-byte unchanged.
  4. Every non-identity edit appears in an ordered, schema-versioned ledger with stable rule/reason, original pieces, generated range or deletion marker, and input/output hashes; composed output and provenance are byte-identical on repeat runs and contain no silent edits.
**Plans**: TBD

### Phase 8: Parse Facts & Quality Grading

**Goal**: Users can tell whether each recovered parse is trustworthy from complete, source-mapped facts rather than process success or ERROR count alone.
**Depends on**: Phase 7
**Requirements**: QUAL-01, QUAL-02, QUAL-03
**Success Criteria** (what must be TRUE):
  1. The adapter distinguishes timeout, no-tree, invocation/ABI failure, and a returned recovery tree, and records every `ERROR` and `MISSING` separately with generated range, mapped original pieces, named ancestry, structural region, retained anchors, data items, paragraphs, and graph-bearing captures.
  2. Every parse receives exactly one green, amber, or red grade with ordered reason codes under a named policy version, and the result is byte-identical for identical facts and policy.
  3. Timeout, no tree, invalid or incomplete provenance, missing required anchors, division-scale recovery, retained-structure collapse, and lost or unmapped graph captures are observably red regardless of otherwise favorable counts.
  4. Stored facts can be regraded under a different policy without reparsing, while preserving the original facts and making policy-version changes auditable.
**Plans**: TBD

### Phase 9: Secure Review Evidence

**Goal**: Users can review every degraded parse through complete, deterministic evidence that is useful offline but cannot disclose proprietary source or bind to a model provider.
**Depends on**: Phase 8
**Requirements**: REV-01, REV-02, REV-03, REV-04
**Success Criteria** (what must be TRUE):
  1. Every amber or red outcome creates one immutable, idempotent occurrence record with stable identities, facts, grade/reasons, mapped evidence, transform summary, privacy class, cluster identity, and lifecycle state; no degraded observation is overwritten or dropped.
  2. Rebuilding clusters from any occurrence or worker order produces the same versioned structural signatures, IDs, representatives, totals, and severity distributions, with totals exactly reconciling to degraded outcomes and no raw names, paths, literals, or source text in signatures.
  3. An explicitly requested packet is canonical, provider-neutral, allowlisted, size-bounded, and usable offline; canary and prohibited-field scans prove it contains no raw/transformed estate source, reconstructable map, path/member/business identifier, credential, provider SDK, model invocation, or network path.
  4. Reviewers can record classification and disposition and observe resolved, persistent, split, merged, and new lineage across versions without deleting or rewriting earlier occurrences.
**Plans**: TBD

### Phase 10: Complete Estate Benchmark & Differential

**Goal**: Users can reproduce the full estate baseline and determine whether a candidate improves parse trust and semantic retention for the same complete population.
**Depends on**: Phase 9
**Requirements**: BENCH-02, BENCH-03
**Success Criteria** (what must be TRUE):
  1. Two fresh same-version runs account for exactly one outcome for each of the 1,369 manifest programs and emit byte-identical canonical transformed source, maps, assessments, records, clusters, manifests, and summaries; any missing outcome fails the run.
  2. A reference single-worker run and the approved bounded multi-worker run emit identical canonical bytes, while elapsed timing is reported only as noncanonical metadata and no performance SLO is asserted.
  3. A paired baseline/candidate report exposes every grade, `ERROR`/`MISSING`, recovery-span, retained-structure, graph-capture, mapping, timeout/failure, and cluster transition for the same manifest and compatible versions.
  4. Comparison fails visibly on denominator drift, a new hard-red outcome, green regression, mapping regression, or graph-capture loss rather than allowing aggregate improvements to conceal harm.
**Plans**: TBD

### Phase 11: Evidence-Driven Parse Recovery

**Goal**: Users receive measured recovery of selected recurring failures, with each fix applied to the proven owning layer and protected against estate overfitting and parser regression.
**Depends on**: Phase 10
**Requirements**: REC-01, REC-02, REC-03
**Success Criteria** (what must be TRUE):
  1. Every material residual cluster selected for action has an explicit ownership classification: preprocessor, source map, include/catalog, grammar, malformed input, accepted degradation, or infrastructure.
  2. Every promoted candidate shows affected-program count, severity and retained-structure impact, normalized signature, correct preprocessing/map evidence, an invented minimal reproducer, expected benchmark movement, and explicit regression gates before implementation begins.
  3. Grammar changes occur only for residuals classified as grammar-owned and reproduced synthetically; fixtures contain no estate excerpt, and the forest shim API boundary remains unchanged.
  4. Selected fixes reduce or resolve their target signatures on development evidence and remain stable or better on the sealed holdout and full paired benchmark, with no new hard-red, green, mapping, graph-capture, NIST, or existing parser-contract regression. If no generic grammar candidate qualifies, the phase closes with classified evidence and explicit stop conditions rather than speculative widening.
