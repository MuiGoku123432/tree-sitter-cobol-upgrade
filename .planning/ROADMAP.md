# Roadmap: tree-sitter-cobol-upgrade — COBOL grammar: nodes for edges

## Overview

The journey runs delivery-pipe-first, then largest-family-first. Phase 1 proves the `go.mod`
`replace` vendoring path end-to-end with the **unmodified** grammar — cheap to do now, and it
answers the toolchain/ABI question and stands up the estate-leak guard before
there is any finished grammar work to strand behind it. Phases 2–4 then add the three construct
families in measured-volume order — IDMS DML (541 programs / 14,764 statements), `EXEC CICS`
(221 / 3,539), `EXEC SQL` (49 / 489) — each one gated by the same six SPEC §6 acceptance criteria:
cascade gone, nodes named, recall moves, no regressions, standard COBOL unharmed, and delivered as
commits separable from fork-local work (criterion 6 softened 2026-08-28 from "upstreamable").
`EXEC DLI` is not built (locked decision D4, zero occurrences). Phase 2 is also where the
"rises measurably" recall bar becomes a concrete number, once the real slope is visible.

## Phase Details

### Phase 1: Delivery Pipe & Measurement Baseline

**Goal**: A grammar change made in this fork reaches gortex and produces a measured recall number
on the same day it is written — with no upstream merge, no forest regeneration, and no risk of
leaking planning artifacts or proprietary estate source into a public fork.
**Depends on**: Nothing (first phase)
**Requirements**: VEND-01, VEND-02, VEND-03, VEND-04, VEND-05, FORK-02, FORK-03, SEQ-01
**Amended**: 2026-08-28 — FORK-01 and the topic-branch publication workflow deferred; upstream
PRs are not a project goal. Replaced by FORK-03 (commit separability). See
`phases/01-delivery-pipe-measurement-baseline/01-CONTEXT.md` §domain and D-12…D-15.
**Success Criteria** (what must be TRUE):

  1. A change made locally in `grammar.js` appears in gortex's parse output after a documented
     regenerate-and-refresh sequence, run at least twice, with no upstream merge and no
     `go-sitter-forest` regeneration involved.

  2. `cobolprobe` is re-measured through the local vendoring path on the same corpus with the same
     method, and recorded beside the published figures — `.cbl` 15% grammar-alone / 27% with
     `neutralize()`, `.cpy` 0% / 93% — which remain the comparison target and the expected result.
     Those figures were measured through forest v1.9.1. The parser this fork ships and the parser
     forest ships are genuinely different builds (`SYMBOL_COUNT`/`TOKEN_COUNT` 1215/585 here,
     1153/523 there), so a divergence is an acceptable outcome **only when the record states both
     sets of numbers, names the build difference that produced them, and cites the evidence for
     that cause**. A divergence that is merely noted, that asserts a cause without evidence, or
     figures adjusted so the two sets appear to agree, all fail this criterion. Whichever way it
     lands, this run's numbers are the baseline of record every later phase measures its delta
     against.
     *(Amended 2026-08-29 from "reproduces the published recall figures … giving every later phase a
     same-method baseline" — an exact reproduction was never guaranteed; a disclosed,
     evidence-explained divergence is the correct outcome, not a re-measurement failure.
     Re-amended 2026-08-29 after plan 01-03: the first amendment attributed the difference to
     forest being built from an older **grammar** revision. Execution disproved that —
     regenerating this fork's current `grammar.js` with the lockfile-pinned tree-sitter-cli 0.24.5
     yields 1153/523, matching forest exactly, and emits `src/tree_sitter/alloc.h`/`array.h`
     which the committed tree lacks. The stale artifact is this fork's committed `src/parser.c`,
     generated by an older CLI — not forest's grammar. The criterion no longer names a cause;
     plan 01-04 owns establishing it, since this is VEND-03's question.)*

  3. The tree-sitter-cli version question is answered with evidence: the CLI that generates
     `parser.c` yields a parser gortex's `go-tree-sitter v0.25.0` loads, and the effect of the
     0.24.5 → 0.25.x bump on upstream's 13 corpus fixtures is recorded as pass/fail (checking
     upstream's `dependabot/npm_and_yarn/tree-sitter-cli-0.25.3` branch for existing evidence first).

  4. The estate-leak guard can be demonstrated *failing* on a deliberately bad branch and
     *passing* on a clean one, by a re-runnable script: it rejects any `estate/` path, flags added
     COBOL lines with a populated columns 73-80 sequence area, and asserts `/estate/` is still
     excluded via `.git/info/exclude`, not `.gitignore`. It is wired to `pre-push`, the last point
     before source leaves the machine for a public remote.
     *(Amended 2026-08-28 from "two guards" — FORK-01 deferred.)*

  5. The remaining build order is recorded with the measured volumes that justify it — IDMS DML
     (541 programs / 14,764 statements), `EXEC CICS` (221 / 3,539), `EXEC SQL` (49 / 489),
     `EXEC DLI` not built.

### Phase 2: IDMS DML Statement Nodes

**Goal**: IDMS DML statements are walkable AST nodes whose record and set operands can be queried,
the `ACCEPT` ambiguity is provably contained, and the "rises measurably" recall bar becomes a
concrete number.
**Depends on**: Phase 1
**Requirements**: IDMS-01, IDMS-02, IDMS-03, IDMS-04, IDMS-05, IDMS-06, IDMS-07, IDMS-08
**Success Criteria** (what must be TRUE):

  1. A tree-sitter query run over a program containing IDMS DML returns the **record name** and
     **set name** from a DML verb as named captures, and all 14 verbs in the estate's mix — BIND,
     OBTAIN, FIND, READY, ERASE, ACCEPT, GET, STORE, FINISH, MODIFY, CONNECT, ROLLBACK, COMMIT,
     DISCONNECT — parse into named statement nodes with accurate positions rather than ERROR nodes.

  2. Standard COBOL `ACCEPT` parses exactly as it did before. Corpus tests cover both the IDMS
     operand tails (`FROM … CURRENCY`, `… DB-KEY`) and ordinary `ACCEPT` forms, and both pass —
     the rule discriminates on the operand tail, never on the verb alone.

  3. `TestErrorCascade` in `cobolprobe` shows paragraphs and data items following a DML statement
     surviving at parity with a file that lacks the construct.

  4. `.cbl` recall measured through the Phase 1 path rises on the **grammar-alone** axis, and that
     observed slope is converted into a concrete gap-closure target that Phase 3 is then held to.
     The target is expressed as a fraction of the measured gap — `(X - 17,905) / (32,360 - 17,905)`,
     using `docs/baseline.md` §2's raw `dataItems` counts — not as an absolute percentage. The
     terminal condition across Phases 2-3 is grammar-alone >= neutralized, i.e. `neutralize()`
     retires. Blocking: grammar-alone rises and `idms_unparsed_tail` does not grow. Mandatory but
     non-blocking: a miss against the allocated share requires a written cause on file.
     *(Amended 2026-08-29 from "measurably above 27%". That wording compared a grammar-alone number
     against a `neutralize()`-assisted ceiling that already includes IDMS — gortex
     `cobolprobe/neutralize_test.go:24`'s `reDML` rewrites all 14 IDMS verbs to `CONTINUE`. Since
     `neutralize()` also fixes the 169 DCC files containing `EXEC CICS`, grammar-alone after
     IDMS-only work will very likely land below 26.6%, so the original criterion would read as a
     failure while the work succeeded. See
     `phases/02-idms-dml-statement-nodes/02-CONTEXT.md` D-13 and D-15.)*

  5. The work is a self-contained commit or series, separable from all fork-local changes
     (FORK-03), passing `tree-sitter test` and adding no NIST COBOL-85 failure beyond
     the **11** in `skip_tests.txt`, with corpus tests included, no site-specific naming, and every
     fixture a minimal hand-written construct rather than an estate excerpt.

### Phase 3: EXEC CICS Blocks

**Goal**: `EXEC CICS … END-EXEC` blocks are walkable AST nodes whose transaction, program, and map
operands can be queried, unlocking the divisions they currently destroy.
**Depends on**: Phase 2
**Requirements**: CICS-01, CICS-02, CICS-03, CICS-04, CICS-05, CICS-06
**Success Criteria** (what must be TRUE):

  1. A tree-sitter query returns the CICS **transaction name**, **program name**, and **map name**
     as named captures from a program containing `EXEC CICS`.

  2. `EXEC CICS … END-EXEC` blocks parse into named nodes with accurate positions rather than ERROR
     nodes — in a grammar that previously contained zero occurrences of `EXEC` or `CICS`.

  3. `TestErrorCascade` shows the paragraphs following an `EXEC CICS` surviving at parity with a
     file that lacks the construct — against a measured baseline of 1 of 20 surviving.

  4. `.cbl` recall measured through the Phase 1 path closes **100% of the measured 1,409-item
     `paragraph_header` gap — grammar-alone `.cbl` `paragraph_header` >= 16,732** — on the same
     grammar-alone axis and under the same direction-hard / magnitude-explained rule (D-15).

     The axis is the `paragraph_header` counter in
     `cobolprobe/neutralize_test.go` (named verbatim to disambiguate it from the different,
     much smaller counter in `probe_test.go`). Phase 3 must first reconstruct the missing
     Phase 1 `paragraph_header` baseline (check out the pre-Phase-2 grammar, run
     `forest-shim/refresh.sh`, re-run the probe) before the delta can be read.

     *(Re-scoped 2026-09-09 per Phase 3 D-16a–d. The prior wording held Phase 3 to
     `dataItems >= 18,772`. That axis is unsatisfiable for this phase: 0 of the 169 `.cbl`
     containing `EXEC CICS` have the construct before `PROCEDURE DIVISION`, and the cascade
     harness measures `EXEC CICS` costing 19 of 20 paragraphs while costing 0 data items. A
     phase that fixes CICS cannot move a DATA DIVISION metric. The DATA DIVISION gap is
     dominated by `SCHEMA SECTION`, which locked decision D3 assigns to preprocessing.
     Originally amended 2026-08-29 alongside Phase 2 criterion 4; value set 2026-09-04,
     `docs/baseline.md` §4.)*

  5. The work is a self-contained commit or series, separable from all fork-local changes
     (FORK-03), passing `tree-sitter test` and adding no NIST COBOL-85 failure beyond
     the **11** in `skip_tests.txt`, with corpus tests included, no site-specific naming, and every
     fixture a minimal hand-written construct rather than an estate excerpt.
